# YOLO OBB 动作检测程序

本目录包含工业相机采集、YOLO OBB 推理、普通动作顺序检测、ROI 定位检测、生产统计和 Windows 便携打包程序。

现场使用请先看 [docs/使用说明.md](docs/使用说明.md)，主要讲 `config.json` 怎么用，以及 ROI 区域怎么创建模板。便携包内还有 `YOLO动作检测系统_简易操作手册.docx`。

## 启动与打包

源码启动：

```powershell
cd yolo_action_detection
..\.venv\Scripts\python.exe src\main.py
```

生成正式便携目录：

```powershell
cd yolo_action_detection
.\packaging\build_yolo.bat
```

输出目录为 `dist\YOLOActionDetection`。目标电脑必须复制整个目录，不能只复制 EXE。

## 两种检测模式

### 普通动作模式

关闭“ROI 定位检测”时，程序继续按“模型与步骤”中的类别顺序推进。后续类别在当前类别尚未完成时稳定出现，会触发错序 NG。该模式的行为与原程序一致。开始检测后，主画面会叠加 MediaPipe 手部 21 点骨架，只供观察操作姿态，不参与 PASS/NG、统计或证据。Hands 缺失或失败时自动降级，不影响顺序检测。ROI 定位检测模式不启用手部骨架。

### ROI 定位检测模式

开启"ROI 定位检测"后，程序不使用类别顺序、产品 ID 或目标追踪。每轮流程如下：

1. 启用模板定位时，每帧先在“搜索 ROI”内执行固定比例、多角度边缘模板匹配；匹配成功才执行整图 YOLO，未匹配时跳过该帧 YOLO。
2. 边缘模板得分达到阈值即触发本轮；未启用模板时，识别 ROI 内出现任意待检类别即触发。
3. 触发后立即统计"识别 ROI"内的所有平级待检类别。
4. 每个类别的实际数量必须恰好等于配置数量，少一个或多一个都属于不匹配。
5. 每类独立累计 PASS/NG 稳定帧；某类 PASS 后在本轮锁存，不会因后续漏检撤销。
6. 任意未完成类别达到 NG 稳定帧，整轮 FAIL；全部类别锁存后，整轮 PASS。
7. PASS 或 FAIL 都只生成一次统计、声音和证据。完成一轮间隔到期后，当前帧可以直接触发下一轮，不要求目标先离开。

### 模板匹配定位

启用"模板匹配定位"后，系统用 OpenCV 边缘 NCC 模板匹配做定位触发，不需要为定位单独训练模型。流程：

1. 在配置页刷新静态帧，通过 ROI 类型下拉框选择“识别 ROI”“模板 ROI”或“搜索 ROI”，点击“创建/替换 ROI”后拖拽调整。
2. 每种 ROI 调整完成后点击编辑器下方“保存当前 ROI”。下拉框选中哪种，就只保存哪种，不覆盖另外两种草稿。
3. 三种 ROI 完全独立，不要求重叠或相互包含：模板 ROI 只用于截取并创建模板；搜索 ROI 只限制运行时查找范围；识别 ROI 只用于类别数量判断。
4. 保存模板 ROI 时，程序提取真实边缘并在模板 ROI 自身范围回查，不要求搜索 ROI 或识别 ROI 已配置。
5. 回查成功后，静态原图直接显示绿色真实轮廓、绿色外框和“创建得分”；配置页不再显示单独的模板裁剪预览。不满意时重新框选模板 ROI 并保存即可覆盖。
6. 回查失败时显示红色原因，不覆盖旧模板、旧配置或旧运行处理器。三种 ROI 完成后，启用对应开关并点击页面底部“验证并保存”统一应用运行配置。
7. 运行时只在搜索 ROI 内找一个最高分定位结果；定位成功后仍对整图执行现有 YOLO，并用固定识别 ROI 判断类别和数量。可配置匹配阈值、旋转角度范围和角度步进，固定比例不做缩放搜索。

模板固定保存为实际 `config.json` 同级的 `locator_template.png`。模板缺失、不可读、有效边缘不足、搜索 ROI 缺失或模板门控处理器加载失败时，程序会明确报错并禁止开始检测，不会静默退回普通 YOLO。

关闭模板匹配定位时，系统退化为识别 ROI 内出现任意待检类别即触发本轮。

### ROI 模式 FAIL 告警弹窗

ROI 模式判定 NG 时，系统自动弹出模态告警窗口：

- 窗口冻结真正触发本轮 NG 的同一张 YOLO 推理帧，并严格裁剪为当前识别 ROI，不使用弹窗时刻的最新预览画面，也不增加裁剪边距；
- 画面只绘制中心点位于识别 ROI 内目标的绿色旋转框；框线越过 ROI 边界时自然裁切，ROI 外目标不显示；
- 弹窗内容区只显示带框画面，不显示类别名、置信度、跟踪 ID、ROI 框、数量摘要或操作提示；
- 裁剪图保持宽高比并自动放大到弹窗可用区域；正常主页面仍显示整张相机画面；
- 告警期间 FAIL 提示音循环播放，检测不停止；连续多轮 NG 时只把画面替换为最新一轮的同帧检测图；
- 按下键盘回车键（主键盘或小键盘）关闭窗口并停止声音；回车只关闭窗口，不影响检测结果或统计。

在配置页“操作反馈”中开启“失败证据保存”后，每个完成的 ROI NG 轮次只保存一次证据：

- 事件目录仍只包含一个 `frame.jpg` 和一个 `metadata.json`，不另外保存无框原图；
- `frame.jpg` 与 NG 弹窗使用相同推理帧和相同识别 ROI 裁剪，只显示中心点位于 ROI 内的绿色 OBB，不显示文字或 ROI；
- `metadata.json` 只记录 ROI 内目标，目标坐标以裁剪图左上角为 `(0, 0)`，并通过 `source_roi` 记录裁剪区在原图中的位置和原图尺寸；
- 识别 ROI 内没有 detections 时仍保存该 NG 同帧无框裁剪图；同帧缺失、帧编号不一致或 ROI 无效时禁止使用整图或最新相机画面替代；
- 保存失败不影响本轮 NG 统计、弹窗、报警或下一轮检测。

## 配置步骤

1. 打开相机，确认主画面正常。
2. 打开"配置 / 模型与步骤"，选择 `.onnx` 或 `.pt` 模型。
3. 填写需要判定的平级类别名称和精确数量。名称必须与当前模型类别完全一致。
4. 打开"ROI 配置"，点击"刷新画面"，程序复制相机最新帧作为静态底图。
5. 在 ROI 类型下拉框选择“识别 ROI”，点击“创建/替换 ROI”，框住待检区域，再点击下方“保存当前 ROI”。
6. 选择“模板 ROI”，框住轮廓清晰的定位目标并点击“保存当前 ROI”；确认原图出现绿色轮廓、绿色外框和创建得分。
7. 选择“搜索 ROI”，框住运行时允许查找模板的范围并点击“保存当前 ROI”。搜索 ROI 与模板 ROI 不要求重叠或包含。
8. 开启"ROI 定位检测"和“模板匹配定位”。
9. 如需保存 ROI NG 带框图片，在“操作反馈”开启“失败证据保存”。
10. 在"动作判定"设置通过稳定帧、NG 稳定帧和完成一轮间隔。
11. 点击页面底部"验证并保存"统一应用配置。配置有任何错误时，界面会列出具体字段并阻止开始检测。

ROI 使用相对于原始相机图像的归一化矩形，分辨率或界面缩放变化不会改变区域含义。相机物理位置、镜头、硬件裁剪或视野变化后，必须刷新静态帧并重新框选。

## 运行画面

模板匹配定位启用时，主画面只显示搜索 ROI 框。模板轮廓、得分、角度、中心、模板 ROI、识别 ROI 和 ROI 类别数量不叠加在相机画面上；类别状态与本轮 PASS/NG 继续显示在右侧状态区域。

程序不会显示或依赖产品追踪 ID。每完成一轮固定统计一次。

## 旧配置处理

当前配置版本为 `config_schema_version: 4`。版本 3 会窄迁移到版本 4，完整保留模型、类别、数量、相机、识别 ROI、声音、PASS/FAIL 帧数和完成间隔，仅新增空搜索 ROI 与默认角度步进。版本 0/1/2 时：

- 程序允许打开配置页并保留通用模型、相机和类别字段，便于人工修复；
- 程序禁止开始检测，并显示"配置版本无效"；
- 不会把旧字段静默转换成默认配置；
- 正式打包脚本会拒绝旧配置。

升级其他电脑时，请删除旧便携目录，复制完整新版 `YOLOActionDetection` 目录，然后确认相机、模型、三种 ROI 和模板均可用。

同一开发电脑再次执行 `packaging\build_yolo.bat` 时，脚本会在清理便携目录前备份并恢复现有 `dist\YOLOActionDetection\config.json` 和 `locator_template.png`，不会覆盖已经调好的模型、类别、ROI、相机、模板和节拍参数。

## 静态图片验收

静态图片验收和实时程序共用配置校验、ROI 几何与轮次引擎：

```powershell
..\.venv\Scripts\python.exe src\validate_onnx_picture.py `
  --image test.jpg `
  --model config\sanrepian2.onnx `
  --roi-config config\config.json `
  --output-dir outputs\roi_picture_validation `
  --conf 0.65 --iou 0.5
```

输出 JSON 的 `roi_inspection` 包含定位实际/配置数量、每个待检类别的实际/配置数量、稳定帧和整轮事件。`pass` 返回退出码 `0`；配置错误、定位未匹配、检查中或 `ng` 返回非零退出码。

## 相机与亮度

“工业相机”页面会重新枚举在线迈德相机，并按 SN 保存选择。相机选择只有保存后才应用：

- 当前相机 SN 未变化时不重启采集；
- SN 变化时停止检测、关闭旧相机、清空本轮与画面，再打开新相机；
- 相机切换和关闭不会清零生产统计；
- 亮度可通过 `manual` 参数模式下的曝光时间调整。

## 目标电脑诊断

便携目录中双击 `diagnose.bat`。完成后检查：

- `logs\startup_diagnostics.log`：运行环境、配置、模型、ONNX Runtime、相机和完整异常；
- `logs\portable_smoke_test.log`：处理器、模型类别、配置校验、声音、主题和输出目录自检。

诊断退出码：`0` 正常，`1` 配置无效，`2` 模型缺失，`3` 声音缺失，`4` 输出目录不可写，`5` 主题依赖缺失，`6` 处理器加载失败。

## 关键配置

| 配置项 | 说明 |
| --- | --- |
| `config_schema_version` | 当前必须为 `4` |
| `roi_inspection_enabled` | ROI 定位检测开关 |
| `roi_template_enabled` | 边缘模板定位开关 |
| `roi_template_path` | 相对于实际 `config.json` 目录的模板路径 |
| `roi_template_match_threshold` | 模板匹配分数阈值 |
| `roi_template_angle_range` | 模板允许旋转角度范围 |
| `roi_template_angle_step` | 多角度搜索步进 |
| `roi_template_rect` | 创建模板时的归一化框选区域 |
| `roi_template_search_rect` | 独立的运行时模板搜索范围，不要求包含模板 ROI |
| `roi_inspection_rect` | 归一化识别矩形 |
| `category_names/category_counts` | 平级待检类别和精确数量 |
| `action_pass_stable_frames` | 每类数量正确的连续帧阈值 |
| `action_ng_stable_frames` | 任意未完成类别数量错误的连续帧阈值 |
| `round_cooldown_seconds` | PASS/FAIL 后到下一轮的间隔 |
