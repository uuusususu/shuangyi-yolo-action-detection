# LSTM 产线试用与验证说明

日期：2026-10-15。

本轮修复用于把工作台的连续 LSTM 正确接入产线，并修复模型切换、配置失败回滚、跨轮动作、采样和证据归属问题。真实产线由用户试用，当前不能视为已通过目标硬件验收。

## 一、使用哪种模式

| ROI 定位检测 | 步骤顺序约束 | 实际判定 |
| --- | --- | --- |
| 开 | 任意 | 原 ROI / YOLO |
| 关 | 关 | 原 YOLO |
| 关 | 开 | 连续 LSTM 完整动作＋该段内全部必需 YOLO 类别 |

动作模式中填写的是动作名称。配置集合必须和模型所有非空闲动作完全一致、无重复；顺序可以按工位 SOP 配置。步骤数量必须为 1。模型包缺失、指纹不同或类别不一致时阻止启动，不能把模型加载失败当成产品 NG，也不能自动退回 YOLO。

现有 `test` 工程的动作映射为：`c1790157821705` → 包装，`c1790158334094` → 封装，`idle` → 空闲。只适用于核实过的这组 ID，其他工程必须提供自己的确认映射。

## 二、模型准备与源码启动

在项目根目录 `E:\双翼科技项目\动作检测` 执行。每个部署目录必须为新目录；工具不会覆盖源训练轮次。

```powershell
Set-Location 'E:\双翼科技项目\动作检测'
@'
{"idle":"空闲","c1790157821705":"包装","c1790158334094":"封装"}

  .\build\现场动作模型包 `
  --mapping .\build\action-mapping.json

```

Windows PowerShell 5.1 不支持 `utf8NoBOM` 时，改用以下写入方式：

```powershell
$mapping = '{"idle":"空闲","c1790157821705":"包装","c1790158334094":"封装"}'
[System.IO.File]::WriteAllText((Join-Path (Get-Location) 'build\action-mapping.json'), $mapping, [System.Text.UTF8Encoding]::new($false))
```

在配置页选择模型包目录，YOLO 使用该轮训练契约绑定的 `zongjian1013.onnx`，阈值 0.6。不要用其他工位的 YOLO 代替；模型包保存了文件指纹。本例轮次时间基为 6.227463 fps，最短动作段为 1.92 秒，两类动作都要求充电器、路由器、网线、纸盒、合盖。要求原样来自已有契约，本次未重新训练或修改标注。

保存配置前先备份现场整个程序目录、`config.json` 和模型包。新代码的候选校验与配置备份不能代替旧程序的整体备份。不要把本机旧工位配置直接覆盖到另一个工位。

## 四、现场逐项测试

先用不触发真实放行的试用工位，记录实际硬件、相机、曝光、光照、帧率和模型指纹。每一项记录预期、实际、测试时间和对应日志或图片。

| 项目 | 操作 | 预期 |
| --- | --- | --- |
| 模式路由 | 分别测试上述三种开关组合 | 动作模式才消费 LSTM 完成事件；其余模式保持既有 YOLO / ROI 行为 |
| 类别一致 | 在副本中改错动作名或删除一个动作 | 保存或启动明确报错，不混用 YOLO 步骤 |
| 模型失败回滚 | 在副本中选择坏包、错 YOLO、坏权重 | 保存失败，磁盘配置、运行处理器与会话保持旧版一致 |
| 完整动作 | 包装、封装依 SOP 完整执行且该段零件齐全 | 等后继稳定段确认前一动作结束后才推进；整轮只统计一次 |
| 缺件 | 完整执行某动作，但该动作段始终不出现一个必需类别 | 该动作 NG、本轮结束，日志列出缺项；后一动作出现的零件不能补前段 |
| 同段累计 | 让所需类别在同一段不同帧依次出现 | 类别可以累计，不要求同帧或规定零件先后顺序 |
| 错序 | 首步通过后完整执行未来步骤 | 错序 NG；首步前的其他合格动作不能提前锁存 PASS |
| 重复事件 | 同一动作段持续保持，或重复完成已通过步骤 | 不重复推进、声音、计数或保存证据 |
| 跨轮 | 在冷却期间开始动作，进入新轮后才结束 | 该跨轮动作不能给新轮 PASS；新轮需下一次真实动作起点 |
| 启动截断 | 在动作中间开始检测 | 当前截断段不 PASS，等待新边界 |
| 停止尾段 | 最后动作尚未确认结束时停止，再恢复 | 停止不补 PASS；恢复重新等待边界 |
| 断流 | 停止供帧超过两个契约采样间隔后恢复 | 故障停止动作放行、清理时序状态；不复用旧动作或零件 |
| 证据归属 | 让前一动作缺件、后一动作画面明显不同 | NG 图片和检测框属于边界源帧，元数据另记真实决策帧 |
| 新包重载 | 保存不同有效动作包或改变包中文件 | 实际模型与会话更换，不能只显示新路径 |

本例两个采样间隔约为 0.321 秒。动作确认还需要后继类别保持到最短段要求，约 1.92 秒加采样和计算耗时；不能按动作结束当帧就应 PASS 来验收。现场须记录动作结束到决策的实际延迟、采集/推理速率与采样覆盖，达不到时间基时不应放行。

## 五、手部问题的边界

本次保留 lite、检测阈值 0.5、追踪阈值 0.5 和视频追踪模式。修复的是手部资源来源、会话生命周期、故障识别和特征缓存身份，尚未证明解决白手套、遮挡、低帧率和运动模糊造成的漏检。

模型正常但没检出手时按原训练规则填零；加载或推理异常时明确故障。没有把旧骨架保留成当前真实输入，没有无依据降低阈值或直接换 full。若现场清晰、连续采集仍大段掉点，请保留相同机位、手套、光照下的原始视频，用可见手人工标注和最长连续丢失时间判断；只看骨架更平滑不足以证明可靠。

工作台换模型或手部参数后，特征缓存会按新身份重抽；已有训练权重仍绑定原输入配置。本次保留旧 run 和特征，不自动重训。实际改变手部模型、预处理或特征结构，需要新版本特征和重新训练验证。

已有工作台进程需要正常退出后重新启动，才会加载这次源码修复：在项目根目录执行 `.\.venv\Scripts\python.exe -m lstm_workbench`。不要把旧进程尚未重启时的显示当成新版验证结果。
