# LSTM 产线部署与验证说明

更新日期：2026-10-26。适用于本次重新构建的独立便携包，目标相机和真实产线准确率仍需现场验收。

## 一、复制哪一个目录

新交付目录：`build/production-delivery-20261026/dist/YOLOActionDetection`。复制整个 `YOLOActionDetection` 文件夹到目标电脑的新目录，不能只复制 EXE，也不能漏掉 `_internal`、`config`、`models`、`config.json`。

旧目录 `build/lstm-delivery-20261015` 保留作回退，不作为本次最新版。退出旧程序后运行新目录的 `start.bat` 或 `YOLOActionDetection.exe`。升级前保留目标电脑的整个旧程序目录、配置和证据。

## 二、内置模型与路径

- 动作模型：工作台 `test` 工程 `20261020-174254`，部署到 `models/action`。
- YOLO：`config/zongjian1013.onnx`，阈值 0.6，必须与动作契约指纹一致。
- SOP：包装、封装，每步数量为 1；ROI 关闭、顺序约束开启。
- 包装必检：充电器、路由器、网线、纸盒；封装必检：合盖。
- 当前动作权重不使用手部关键点，画面骨架不代表模型输入。

上述模型都随包携带。无需复制工作台、训练视频、Python 环境或本机 E 盘训练目录。模型和 EXE 指纹见包内 `release_manifest.json`，验证证据见 `验证记录.md`。

## 三、目标电脑首次启动

1. 安装与工业相机匹配的 64 位 SDK/驱动。
2. 双击 `diagnose.bat`。日志中必须同时看到 `lstm=ok`、`torch_forward=ok` 和最终 `[portable-smoke] ok`。它只验证依赖、模型资源及真实前向，不验证现场图像准确率。
3. 打开程序，在配置页刷新工业相机列表，选择该工位实际相机 SN；包内保留的相机选择来自开发机，不能代替目标工位选择。
4. 核对包装、封装顺序和现场所需零件。模型路径保持包内相对路径；仅在确实更换整套有效模型时重新选择。
5. 保存配置，先以不连接实际放行设备的方式试跑，记录结果及日志。

正常模式：ROI 开时使用 ROI 检测；ROI 关且顺序约束关时使用原 YOLO；ROI 关且顺序约束开时使用完整 LSTM 动作事件和段内必检零件。

## 四、本次连续作业判定

- 新一件以完整 SOP 首步为边界。包装已通过后又出现独立完整包装，上一件未做封装就记 NG，后一包装只在新轮处理。
- 没有产品 ID 时无法可靠区分同件返工和新件。本次采用保守规则：再次完整首步按新件处理；需要返工时应由工艺人员确认记录。
- 正常续轮先等待新包装，上一件尾部重复封装不再生成额外 NG。
- 结果显示停留只管显示，动作及时处理；显示停留 0/1/5/60 秒不应导致排队丢件或漏计数。
- 真正缺件、缺步和错序仍记 NG。停止、关相机、模型故障不补发未完成尾段的 PASS。
- 模型一直输出同一动作而没有确认结束边界时继续等待，不用超时猜测动作完成。模型准确率和边界延迟须现场验证。
- NG 证据保存真正出错动作的边界图片、缺件、时间和模型标识，后续合格动作不能覆盖。

## 五、现场验收清单

| 场景 | 预期 |
| --- | --- |
| 连续正常包装、封装至少 20 件 | 每件一次 PASS，计数与人工一致 |
| 包装后不封装，直接进行下一件包装 | 前件缺封装 NG，后件正常独立判定 |
| 包装段始终少一种必检零件 | 该包装缺件，不误报成封装缺件 |
| 一件结束后出现尾部封装片段 | 不额外多计一轮 NG |
| 不同结果显示停留与连续快节拍 | 不因显示停留丢动作或漏统计 |
| 缺件后画面继续变化 | NG 图片仍对应出错动作，元数据帧号一致 |
| 动作中途开始、停止后重启 | 截断动作不补 PASS，旧事件不进入新运行 |
| 相机断开、模型错误 | 明确报告故障，停止放行，保留可定位日志 |

## 六、带回日志与回退

问题复现后带回完整 `logs`、`outputs/evidence`、现场 `config.json`、包内 `release_manifest.json`，以及失败动作前后的连续原始视频。主要日志为 `action_trace.log`、`startup_diagnostics.log`、`portable_smoke_test.log`。

回退：退出新程序，启动此前保留的旧完整目录。不要混拷不同版本的 EXE 与 `_internal`。本机源码回归、自检、EXE 内代码核对和迁移测试各有独立记录；它们不替代目标电脑与真实工艺验收。未经用户确认不归档 OpenSpec 变更。
