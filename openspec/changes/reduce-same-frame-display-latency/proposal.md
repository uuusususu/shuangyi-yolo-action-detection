## Why

现场要求“框必须严格贴在对应像素上”，因此检测开启后主画面锁定在推理所用的那一帧，只叠加同一 `source_frame_id` 的检测框。这个语义是正确的，必须保留。

代价是**主画面的延迟和刷新率完全等于一个推理周期**。现场表现为“目标在走、框在后面追”。经过排查，这个现象有两个彼此独立的成因，且都与推理算力无关：

**成因一：推理结果事件在界面队列中积压。** 推理线程每完成一帧就投递一次跨线程事件，界面侧没有任何丢弃或合并机制。只要界面处理一个事件的耗时超过推理一帧的耗时，队列就单调增长，界面将持续处理队列头部**越来越旧**的帧，延迟随运行时间累积而不会自行恢复。同时每个积压事件都持有一份整帧快照，内存压力同步增长，而 ROI 引擎与统计也会基于过期帧做判定。推理线程本身已经正确实现了“只吃最新帧、丢弃中间帧”，但这个原则没有延伸到界面侧。

**成因二：与新数据无关的重复渲染。** 相机打开后固定周期定时器持续触发渲染，检测开启时也不停止。两次推理之间，待显示帧与检测结果都没有变化，却要重新拷贝、重画、重做色彩转换与缩放，产生逐像素完全相同的结果。渲染频率因此挂钩于界面刷新频率，而非新数据到达频率。渲染是内存密集型负载，与同为内存密集型的推理争抢带宽和 CPU，反过来延长推理周期。

在此基础上，链路上还有若干与判定无关的固定浪费：完整分辨率上的平滑缩放被放在色彩转换之后（最重的一步压在最大的数据上）、采集后为预览与推理各做一次整图拷贝、模板匹配对完整画面灰度化后只使用其中一小块搜索窗口、模板匹配逐帧重算与画面无关的静态量并重复旋转同一点集。

这些开销的绝对量随相机分辨率线性放大——当前 2000 万像素相机使其尤为突出——但**它们在任何分辨率下都是净浪费**。需要注意的是，ONNX 推理输入固定为 640×640，其耗时与相机分辨率无关（实测约 41ms）；因此后续更换低像素相机后，本提案的各项优化依然成立，只是绝对收益下降，而推理耗时会重新成为主导项。

此外还有两处与“框严格贴合”语义冲突或会误导现场的问题：

- 停止检测后的一小段时间窗口内，系统仍会把最后一批检测框叠加到不断刷新的最新预览帧上，造成框漂移。
- 一批仅对 Ultralytics 路径有效的推理参数在使用 ONNX 模型时完全不起作用，但在配置页照常可编辑，现场调整不会产生任何效果。

## What Changes

- **界面只处理最新推理结果**：界面侧 MUST 丢弃积压的过期推理事件，只处理最新的一个，使延迟不随运行时间累积。
- **固化同帧叠加语义**：把“检测中主画面显示推理同帧、只叠加同帧检测框”从实现细节提升为受规格约束的行为，防止后续改动为了让画面显得流畅而把过期框叠回最新预览帧。
- **停止检测后立即停止绘制检测框**：消除停止检测后的框漂移窗口。
- **内容未变化时跳过渲染**：待显示帧、检测结果与显示控件尺寸均未变化时不渲染。该约束同时覆盖检测与预览两种状态——相机帧率可能低于界面刷新频率，预览状态同样存在对同一帧的重复渲染。
- **缩放前移**：先把画面缩放到显示控件尺寸，再做色彩转换与 Qt 图像构造，取消完整分辨率上的平滑缩放。检测框仍绘制于完整分辨率帧，以保证框与画面像素严格对应。
- **采集帧以只读快照共享**：预览与推理引用同一份快照，取消两次整图拷贝。
- **模板匹配避免整帧遍历**：搜索窗口先按搜索 ROI 裁剪再灰度化。
- **模板匹配消除重复计算**：缓存与画面无关的静态量；同一角度的点集旋转在一次位姿搜索中复用；两个梯度场的采样坐标与插值权重只计算一次；仅供诊断的角度响应曲线只在诊断会话激活时计算。以上均为等价优化，匹配得分、位姿与匹配结论 MUST 保持不变。
- **ONNX 会话选项可配置**：CPU intra-op 线程数与图优化级别纳入配置并保存即生效。
- **无效推理参数不再误导现场**：使用 ONNX 模型时，仅对 Ultralytics 路径有效的推理参数在配置页 MUST 不可编辑，跟踪 ID 叠加开关在无跟踪信息时同理。
- **分段耗时可观测**：采集、模板匹配、YOLO 推理、界面渲染的耗时分别上报，使“周期慢在哪一段”可被现场直接读出。

本变更 **不改变** 任何判定逻辑：PASS/NG 结论、计数、证据图、声音反馈、ROI 与步骤引擎行为全部保持现状。检测输入的降采样插值方式**不在本次范围内**——它会改变检测结果，需与精度对比验证一起单独评估。

## Capabilities

### New Capabilities

- `realtime-inference-display-latency`: 推理结果事件的处理策略、检测中主画面与推理帧的绑定关系、渲染触发条件、完整分辨率整图操作的最小化约束、模板匹配优化的等价性约束，以及分段耗时可观测性。

### Modified Capabilities

- `runtime-model-configuration`: 保存即生效的运行时模型配置范围扩展到 ONNX 会话线程数与图优化级别；并要求仅对特定推理后端有效的参数不得在其他后端下可编辑。

## Impact

**受影响代码**

- `src/ui/main_window.py`：推理事件积压丢弃、渲染触发条件、渲染路径顺序、停止检测后的绘制行为、分段耗时展示。
- `src/camera/camera_worker.py`：采集与推理链路上的冗余拷贝、分段耗时采集与上报、移除未使用的信号。
- `src/template_matching/shape_model.py`：搜索窗口裁剪顺序、静态量缓存、旋转与采样复用、诊断字段条件计算。
- `src/yolo_runtime/template_gated_processor.py`：向匹配器传递诊断激活状态、分段耗时。
- `src/yolo_runtime/onnx_obb_processor.py`、`src/main.py`：ONNX 会话选项。
- `src/config.py`、`src/ui/config_page.py`：新增 ONNX 会话配置项及其编辑入口；按模型格式禁用无效推理参数。

**受影响测试**

- `tests/test_shape_model.py`、`tests/test_template_gated_processor.py`、`tests/test_template_match_diagnostics.py`：补充优化前后结果等价的断言。
- `tests/test_ui_redesign.py`、`tests/test_runtime_model_configuration.py`、`tests/test_roi_config_page.py`：覆盖事件积压丢弃、渲染触发条件、停止检测后的绘制行为与新增配置项。

**风险**

- 丢弃积压事件意味着部分推理结果不会进入界面处理。必须确保被丢弃的只是显示与其派生状态，判定所需的轮次结果不得因此丢失。
- 检测中停止重复渲染后，若推理线程异常停顿，画面会停在最后一次推理帧。这与同帧语义一致，但需要状态区显式提示，避免被误读为程序卡死。
- 模板匹配优化涉及数值路径，必须以等价性测试兜底，不得以“分数接近”放行。
- 取消采集拷贝后预览与推理共享同一数组，需以只读约束和副本语义防止相互污染。
