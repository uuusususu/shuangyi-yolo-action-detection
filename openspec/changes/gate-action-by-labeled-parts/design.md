## Context

训练台在 `lstm_workbench/`。一条视频的特征是 `features/<片子>.npy`，每一帧长度 `零件类别数 × 5 + 126`。每个零件占 5 个数，第 1 个是置信度。抽特征时低于 `yolo_conf_threshold` 的框已经写成 0，所以置信度大于 0 就是这一帧看见了这个零件。后面 126 个数是手。

动作模型只对一段时间输出一个类别，例如包装、封装或空闲。它不知道「缺了网线」。零件检测的结果已经在特征里，不需要再训一个模型来回答缺不缺。

当前包装标注里，充电器、网线、路由器、纸盒在每一段里都至少出现过。封装标注里，网线和路由器整段都是 0。契约必须按各类自己的标注来记，不能把包装的零件要求套到封装上。

## Goals / Non-Goals

**Goals:**

- 开训时从这一轮的标注段里抽出每类动作出现过的零件，写进该轮契约。
- 验证时动作模型和零件缺件同时生效。动作不对，失败。动作对但契约里的零件少一件，失败，并指出缺哪一件。
- 只要求出现过，不要求同一帧，不要求先后。
- 旧轮次没有这份记录时，验证行为不变。

**Non-Goals:**

- 不训练零件模型，不改 YOLO，不改手部模型。
- 不把顺序写进规则。不要求三件在同一帧同时可见。
- 不改工位 `StepSequenceEngine` 和 ROI。本提案只到训练台的训练与结果页验证。
- 不把空闲拿来卡零件。

## Decisions

1. 零件是否出现，只读特征里该零件的置信度。置信度大于 0 记为出现过。不另做一次检测，也不读取验证画面上的框文件。框文件只负责播放时把框画出来。

2. 开训、特征已经按时间基对齐之后，扫描这一轮训练段和验证段。对每个动作类别（不含空闲）统计零件名。某一件在该类任一帧上置信度大于 0，就列入该类。一类下面没有任何零件出现过，契约里该类对应空列表，验证时不卡零件。

3. 契约新增 `required_parts`，键是动作类别 id，值是零件名列表，顺序与 `part_class_names` 一致。例如包装 id 对应 `["充电器", "网线", "路由器", "纸盒"]`。显示名在验证时用当前标注里的类别名；零件名用契约里的字符串，避免标注改名之后对错槽。

4. 验证先按现有动作模型把新视频分成段。`sample_unit` 为 `segment` 的轮次按整段收口，旧轮次仍按原来的逐帧收口。分段完成之后才做零件检查，不把零件检查插进 LSTM 前向。

5. 一段的零件检查只在它的类别 id 存在于 `required_parts` 且列表非空时进行。在这段对应的特征行上，对列表里每个零件看是否至少一帧置信度大于 0。都有则 `part_check` 为 `pass`。否则为 `fail`，`missing_parts` 列出缺的零件名。动作类别本身不是包装（或不是该类）时，不写零件检查，这段因动作不对而失败。

6. 结果页当前动作固定在第一行。通过时写「完成」。失败时写「失败」，后面是缺的零件名。段表增加这一列。没有 `required_parts` 的轮次不显示这一列。

备选是把缺件训练成动作模型的一个新类别。标注里缺件的段和完整段混在一起时，模型仍会把缺件画面认成完成，而且说不出缺的是哪一件。已排除。

## Risks / Trade-offs

- [封装标注里网线和路由器从未出现] → 契约不会要求这两件，封装验证缺了它们也不会失败。要卡这两件，封装的标注段里必须真的出现过。
- [零件名不在 `part_class_names` 里] → 该件视为缺失，这段失败，避免静默放过。
- [验证视频的特征类别顺序与契约不一致] → 沿用现有的模型一致性检查，对不上就拒绝验证，不做零件检查。
- [只在一段里出现过一次也算] → 符合「出现过就可以」。遮挡后的帧不再要求该零件继续可见。

## Migration Plan

旧 `contract.json` 没有 `required_parts`。读到缺这个键时跳过零件检查。新开一轮训练才会写入。不改已有权重文件。回退时不读该键即可，无需迁移旧轮次。

## Open Questions

无。不按顺序，不要求同一帧。空闲不卡。
