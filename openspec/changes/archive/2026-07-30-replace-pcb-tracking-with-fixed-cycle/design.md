## Context

当前第一类别区域判定由 `MultiPcbInspectionEngine` 驱动。引擎会为 ONNX 父类别检测生成或映射业务 `track_id`，并通过 IoU、中心距离和漏检帧数延续父类身份。父类判定状态、等待队列和结果历史都以该 ID 为键。现场相邻 PCB 外观一致且经过相近位置，新 PCB 可能在旧轨迹过期前继承旧 ID 和上一轮状态。

用户已经确认只取消产品追踪 ID。现有业务逻辑保持不变：配置中的第一类别仍是父区域，后续类别只在父区域内计数；类别数量、稳定帧、完成锁存、PASS/NG、声音、证据、UI 以及“完成一轮间隔（秒）”继续使用当前语义。相机采集、图像范围、ROI 和模型处理不属于本变更。

## Goals / Non-Goals

**Goals:**

- 删除第一类别区域模式中的产品 ID 生成、空间匹配、轨迹过期和跨轮次 ID 状态继承。
- 保持第一类别父区域及区域内后续类别判定逻辑不变。
- 使用现有完成一轮间隔作为相邻轮次的唯一状态隔离边界。
- 间隔到期后彻底清空上一轮状态，使相近位置的新 PCB 从空状态重新判定。
- 第一类别区域界面不显示产品追踪 ID。

**Non-Goals:**

- 不增加“必须正好两块 PCB”、左右板状态或新的多板调度规则。
- 不改变 PASS/NG、稳定帧、声音、证据或步骤锁存语义。
- 不增加 ROI、相机裁剪、分辨率兼容改造、自动测速或新节拍参数。
- 不修改普通动作顺序模式。

## Decisions

### 1. 父区域使用轮次内位置槽，不使用产品身份

取消 `_ParentTrack`、`_source_to_business_id`、合成负 ID、空间匹配和轨迹过期。为保留多父区域顺序、稳定帧和完成锁存，当前产品轮次可以按每帧稳定排序使用位置槽。位置槽只表示当前轮次中的处理顺序，不跟随物理产品运动，不读取上游 ID，并在完成一轮间隔结束时整体销毁。位置槽不得写回 `ObbDetection.track_id`，不得用于下一轮身份关联。

`ComponentOwnershipResolver` 的几何规则保持不变；如果其接口当前要求键值，实现应接受轮次内位置槽，而不是产品追踪 ID。

替代方案是缩短轨迹保留帧或调低匹配距离，但仍会在特定速度和位置下发生 ID 转移，不满足“无需追踪”。

### 2. 轮次状态与产品身份解耦

保留现有轮次判定状态和类别稳定逻辑，但轮次状态不再存放或查询产品 `track_id`。当前帧识别到第一类别后，现有流程使用该帧父区域及其子类别观测推进当前轮次。

多父区域数量、选择顺序和现有 UI 行为不是本变更的重新设计内容。实现前先用回归测试固定当前非 ID 行为，只替换状态键和父区域引用方式。

### 3. 完成一轮间隔是唯一的新旧轮次边界

当前轮次按照现有规则完成后，继续使用现有计时器保持结果显示。计时期间不启动下一轮。间隔到期时统一销毁：

- 类别完成状态；
- PASS/NG 稳定帧；
- 结果和缺失类别；
- 声音、证据和统计去重状态；
- 当前父区域的任何临时关联。

清空后，下一次有效第一类别检测从新轮次空状态开始。操作员通过现有间隔适配输送速度，程序不增加第二个时间参数。

### 4. 保持现有对外行为和配置

`round_cooldown_seconds`、类别名称、配置数量和稳定帧字段不变。PASS/NG 是否结束、重试、显示和反馈均由当前行为及其回归测试决定，本变更不重新定义。

如果结果数据结构为兼容其他调用仍保留可选 `track_id` 字段，第一类别区域路径必须始终置空且不得读取；UI 在该模式下不得绘制该字段。

### 5. 不触碰相机与模型输入路径

相机硬件是否裁剪、每帧出现多少 PCB、帧尺寸和 ONNX letterbox 均使用当前实现。本提案不添加验证门槛或相机代码任务，避免把现场配置选择扩大成软件功能。

## Risks / Trade-offs

- [完成一轮间隔设置过短，旧 PCB 仍在画面] → 操作员按现场速度延长现有间隔；本变更不增加身份判断来区分旧板。
- [完成一轮间隔设置过长，下一块 PCB 已经过有效位置] → 操作员缩短现有间隔并通过现场连续运行确认。
- [没有追踪后父区域检测瞬时变化] → 保留现有稳定帧和父子空间归属规则，不引入新的行为语义。
- [轮次内位置槽被误当作产品 ID] → 数据模型和测试明确禁止位置槽写回检测结果、跨轮次保存或显示。
- [未归档旧提案仍要求业务 ID] → 本提案明确取代其 ID 追踪要求；旧提案是否归档仍需用户在本变更验收后确认。

## Migration Plan

1. 先添加失败测试，复现新 PCB 在相近位置继承上一轮状态，并固定第一类别父子逻辑、稳定帧和反馈的现有行为。
2. 移除父类追踪结构，改用帧内临时父区域引用完成子类别归属。
3. 将轮次状态从产品 ID 解耦，并在现有完成一轮间隔到期时统一重置。
4. 隐藏第一类别区域模式的追踪 ID，保持其他 UI 和结果反馈不变。
5. 运行相关测试、完整回归和打包验证；现场通过调节现有间隔确认新旧 PCB 不再继承状态。

回滚时恢复上一版本程序和配置文件；本变更不修改配置格式，因此无需配置迁移。

## Open Questions

无。用户已明确要求只取消追踪 ID，其他第一类别区域判定和完成一轮间隔行为保持不变。
