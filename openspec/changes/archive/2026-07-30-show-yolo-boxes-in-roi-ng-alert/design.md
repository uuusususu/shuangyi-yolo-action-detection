## Context

当前 `CameraWorker` 在推理线程中取得一帧图像和对应的 `source_frame_id`，生成 `DetectionOverlayState` 后更新 `_latest_display_frame`，再通过 `overlay_state_updated` 发送检测字典。`MainWindow` 收到事件并在同一次调用中完成 ROI 轮次判定；当结果为 NG 时，现有 `_show_roi_fail_alert()` 又调用 `_get_feedback_frame()` 读取“此刻最新”的显示帧，并只叠加搜索 ROI。推理线程可能在界面槽函数执行前或弹窗创建前更新显示帧，因此该画面不构成与 NG 检测结果严格绑定的证据。

现有 `RoiFailAlertDialog` 同时包含图片、数量摘要滚动区和操作提示。现场已确认新的弹窗内容只保留图片；图片上绘制该 NG 推理帧中的全部 YOLO OBB 绿色旋转框，不显示任何标签或其他覆盖层。声音循环和回车关闭属于已正常运行的控制链路，必须保持不变。

## Goals / Non-Goals

**Goals:**

- 保证 NG 弹窗中的图像和 YOLO 检测结果具有相同 `source_frame_id`。
- 在冻结帧上绘制全部 YOLO OBB 旋转四边形轮廓，包括识别 ROI 外的检测结果。
- 让弹窗内容区仅显示带绿色检测框的冻结画面。
- 保持现有声音循环、结果去重、弹窗复用和回车关闭行为。
- 用自动化测试锁定同帧绑定和纯图像布局，防止再次退化为最新预览原图。

**Non-Goals:**

- 不推断缺失目标应在图中的理论位置，也不为未检测目标生成虚拟框。
- 不改变 YOLO 推理、置信度阈值、NMS、ROI 数量判定、PASS/NG 稳定帧或轮次间隔。
- 不改变主检测页的覆盖层样式、生产统计、FAIL 证据文件或声音配置。
- 不新增类别名、置信度、跟踪 ID、ROI 框、数量摘要或操作提示。

## Decisions

### 1. 将推理帧与检测结果作为同一事件载荷传递

`CameraWorker` 在产生 overlay 的位置，把当前推理使用的帧快照与 `_overlay_to_dict()` 的结果一起发送。载荷中的帧与 `source_frame_id`、detections 来自同一次 `process_frame()` 调用；界面不得在 NG 路径中重新调用 `get_latest_preview_frame()` 或无条件读取新的 `_latest_display_frame`。

选择该方案是因为只保存“最新显示帧”无法在界面事件积压或下一次推理先完成时证明同帧一致性。另一种方案是增加按 ID 查询的环形帧缓存，但它需要容量和过期策略，仍可能在界面延迟时丢失目标帧；本次需求只需要消费当前推理事件，直接随事件传递更简单且确定。

帧对象只在事件生命周期和当前打开的 NG 弹窗中保留。绘制前创建副本，避免 OpenCV 原地绘图污染相机缓冲或后续证据保存。

### 2. ROI 结果处理显式接收当前推理事件

`MainWindow._on_overlay_updated()` 在调用 ROI 引擎后，把本次 payload 继续传给结果处理函数。NG 分支从该 payload 读取帧和 detections，构造弹窗图像；不得依赖 `_last_overlay_data` 或再次读取 worker 的可变“最新值”。`source_frame_id` 不一致或帧无效时不得把另一帧与当前检测框组合，且应写入运行日志便于诊断。

### 3. 使用独立的纯轮廓绘制路径

新增或提取一个只负责检测轮廓的绘制函数：遍历本次 payload 中全部 detections，对每个至少包含 4 个点的 polygon 使用绿色、固定线宽、闭合折线绘制。该函数不复用会追加类别文字、置信度、跟踪 ID、枪头标记、孔位或 ROI 的主画面 `_draw_overlay()` 完整路径。

选择独立绘制路径可以把“纯框”约束直接测试，避免以后主画面覆盖层增加内容时污染 NG 弹窗。无效 polygon 被跳过，但不得影响其他有效框或弹窗显示。

### 4. 告警弹窗收敛为单一图片内容

`RoiFailAlertDialog` 移除摘要滚动区、摘要累积状态和操作提示标签。刷新接口只接收一张已经完成轮廓绘制的 BGR 图像并替换当前 pixmap。系统标题栏可以保留窗口标题，但 Qt 内容区不得出现额外文字控件。

弹窗已打开又发生新一轮 NG 时，以新一轮的同帧带框图替换旧图；现有循环声音不重新启动。回车键仍清空图片、关闭窗口、发出 `alert_closed`，由 `MainWindow` 停止循环声音。

### 5. 不引入配置和第三方依赖

绿色、线宽和纯图像行为属于固定现场交互，不增加配置项。继续使用现有 OpenCV `polylines` 和 PySide6 图像显示能力，便携包依赖集合不变化。

## Risks / Trade-offs

- [每个推理事件携带帧会增加内存带宽] → 复用当前推理帧对象的稳定引用，并只在绘制 NG 图时复制；不把历史帧加入无界队列。
- [Qt 事件排队期间帧对象被意外修改] → 相机采集采用替换缓冲而非原地复用；界面绘制前仍执行 `.copy()`，测试使用不同像素值的连续帧验证不会串帧。
- [检测结果没有有效 polygon] → 跳过该单个框并记录测试覆盖，仍显示原始 NG 冻结帧，禁止退回另一帧。
- [只画已检测框不能标出未检测目标的理论位置] → 这是已确认的产品取舍；员工通过实际框分布观察，系统不制造无检测证据的位置标记。
- [移除数量摘要降低类别层面的文字解释] → 这是现场明确选择；主页面现有识别项和统计逻辑不变，弹窗专注图像证据。

## Migration Plan

1. 先增加同帧载荷和绘制函数的失败测试，再调整 worker 与主窗口数据传递。
2. 收敛弹窗布局和刷新接口，更新现有摘要相关测试为纯图像断言。
3. 运行 ROI 集成测试、完整测试、编译检查和 OpenSpec 严格校验。
4. 重新生成简易操作手册并构建便携包，使用模拟 NG 帧和实际 ONNX 路径完成冒烟与截图验收。

回滚时可恢复本变更前提交：worker 的 overlay 字典接口和原告警弹窗均没有配置迁移或持久化数据变化。

## Open Questions

无。冻结帧、全部检测框、绿色旋转轮廓、无文字内容以及声音和回车行为均已确认。
