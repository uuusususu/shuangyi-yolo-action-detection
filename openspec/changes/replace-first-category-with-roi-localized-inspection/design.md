## Context

当前区域检查由 `MultiPcbInspectionEngine` 驱动，配置列表第一项被解释为父类别，后续类别通过父区域几何归属、位置槽和轮次调度完成数量判定。即使已经取消产品追踪 ID，完整父目标仍是启动判定的前提；现场同时出现多块相同 PCB 时，模型可能只输出一个完整 PCB 框，导致另一块板上的目标无法进入业务判定。

用户已经确认改为通用固定工位方案：模型定位类别在定位 ROI 中单帧精确达到配置数量后触发一轮；同一帧开始统计识别 ROI 内全部平级配置类别，各类别按现有 PASS/FAIL 帧数独立推进并锁存，PASS 或 FAIL 后沿用现有完成一轮间隔控制下一轮。该模式不区分多个产品，不使用 ID 或追踪，一轮只生成一次统计。

## Goals / Non-Goals

**Goals:**

- 用独立定位类别和定位 ROI 取代第一类别父区域。
- 在一个固定识别 ROI 内执行通用、平级、精确数量判定。
- 提供可视化 ROI 配置页面，并在运行画面显示双 ROI 和数量状态。
- 保留现有类别数量配置、PASS/FAIL 帧数、类别完成锁存、声音、证据、统计和完成一轮间隔。
- 彻底删除旧父区域、位置槽、PCB 专用配置和兼容迁移。
- 让普通动作模式在 ROI 模式关闭时保持不变。

**Non-Goals:**

- 不区分左右 PCB、不为单块产品生成结果，也不按定位数量增加产品统计。
- 不做产品追踪、运动方向判断、定位离开重布防或自动输送测速。
- 不新增模型训练、第二次裁剪推理、动态锚点 ROI、多个定位 ROI 或多个识别 ROI。
- 不改变模型全图推理、相机硬件裁剪、置信度、NMS 或最大目标数配置。

## Decisions

### 1. 新建通用 ROI 轮次引擎并删除父区域引擎

用职责单一的 ROI 轮次引擎替代 `pcb_inspection` 父区域实现。引擎输入仍是一帧完整 `ObbDetection` 列表和图像尺寸，内部只保存轮次状态、每类连续 PASS/FAIL 帧、已完成类别和一次性结果事件，不保存父检测、位置槽或 `track_id`。

建议状态机为：

`WAITING_FOR_LOCATOR -> INSPECTING -> RESULT_HOLD -> WAITING_FOR_LOCATOR`

`WAITING_FOR_LOCATOR` 只检查定位条件；触发后在同一次 `update()` 继续执行识别区判定。`INSPECTING` 不再查询定位条件。PASS 或 FAIL 进入 `RESULT_HOLD`，间隔到期统一清空类别、计数器、结果和反馈去重，再允许当前帧重新触发。

替代方案是在现有 `MultiPcbInspectionEngine` 中把“父类别”替换成虚拟 ROI，但会保留大量无意义的父子、位置槽和 PCB 命名，容易让旧语义继续渗入新模式，因此不采用。

### 2. 配置使用新版本和两个归一化矩形

新增明确配置版本以及以下业务字段，实际命名在实现时保持项目既有命名风格：

- ROI 定位检测开关；
- 定位类别名称；
- 定位目标数量；
- 定位 ROI：`x/y/width/height`，范围为 `0..1`；
- 识别 ROI：`x/y/width/height`，范围为 `0..1`。

继续复用 `category_names`、`category_counts`、现有 PASS 帧数、FAIL 帧数和 `round_cooldown_seconds`。同类型 ROI 只有一个，新建时替换旧值。归一化坐标是业务权威坐标；配置页、运行画面和静态图片验证都必须通过同一个映射/中心点包含函数转换，避免 UI 缩放、相机分辨率和离线验收产生不同语义。

实时相机推理 payload 必须随每一帧携带原始图像 `(width, height)`，ROI 引擎不得以显示控件尺寸或 `(0, 0)` 执行中心点判断。为兼容旧 payload，主窗口可从同帧显示图像恢复原始尺寸；两者都不可用时必须跳过该帧并显示明确错误，而不是让定位线程异常退出。

旧配置不迁移。配置加载层可以读取仍通用的模型/相机字段用于打开界面，但缺少新配置版本时必须把检测配置标记为无效；不得把旧第一类别字段转换成定位字段或生成默认 ROI。

### 3. 定位是单帧精确门控，不是待检步骤

等待状态按检测框中心点筛选定位 ROI 中的定位类别，实际数量必须精确等于配置值。少于或多于都只保持等待，不推进 FAIL。定位成功不要求稳定帧并立即锁存本轮，随后定位类别是否继续存在不影响识别。

定位类别可以同时出现在普通待检配置中。此时触发和业务计数是两次独立筛选：定位使用定位 ROI；业务数量只使用识别 ROI。不得把定位计数直接复制为业务计数。

替代方案是要求定位稳定多帧或定位目标离开后重布防，但用户已经明确定位只需一帧，轮次节奏仅由 PASS/FAIL 帧数和完成间隔控制，因此不采用。

### 4. 类别并行、精确数量、分别锁存

识别状态为每个有效类别维护：配置数量、当前观察数量、连续匹配帧、连续不匹配帧、锁存状态。每帧只统计中心位于识别 ROI 的配置类别：

- `observed == required`：匹配帧加一，不匹配帧清零；
- `observed != required`：匹配帧清零，不匹配帧加一；
- 匹配帧达到 PASS 门槛：类别锁存 PASS，后续不再撤销或累计 FAIL；
- 任意未锁存类别不匹配帧达到 FAIL 门槛：整轮 FAIL；
- 全部有效类别锁存：整轮 PASS。

类别列表顺序不参与 ROI 模式的判定。结果快照包含每类实际/配置数量和失败类别，供主界面、证据和日志复用。一轮只发出一个终局事件，统计固定加一，不乘以定位目标数量。

### 5. ROI 页面使用静态最新帧和单一编辑模型

新增 ROI 页面，但不引入新的图形依赖。页面从相机 worker 请求最新预览帧，复制为静态底图；“刷新画面”替换底图。编辑器维护至多两个矩形对象，创建后通过类型选择设为定位或识别区域，同类型赋值替换旧矩形。拖拽和缩放只更新显示坐标，保存时转换为归一化原图坐标并做范围、正面积和完整性校验。

定位类别使用普通文本框手动填写，待检类别继续在“模型与步骤”页面手动填写。配置页不读取当前处理器类别填充下拉框，也不使用启动时旧处理器的类别拒绝新模型配置；名称与模型是否一致在新模型保存并加载后，于开始检测、离线验收和诊断阶段严格校验。

如果相机尚无有效帧，页面禁用创建并提示先打开相机或刷新画面。运行时只绘制边框和简短标签：定位区显示当前/配置定位数量，识别区配合现有步骤卡显示每类实际/配置数量；不得显示产品 ID。

### 6. 模式开关替换旧入口，普通动作模式隔离

配置 UI 用“ROI 定位检测”替换“第一类别区域检查”。保存配置时根据开关创建且只创建对应引擎：ROI 模式使用新引擎，关闭时使用现有普通步骤引擎。相机关闭、切换、处理器重载和配置重新保存时均清空 ROI 引擎、运行时双 ROI 状态、步骤卡和结果显示，但不清零已有生产统计，沿用现有相机切换约束。

删除旧第一类别/PCB 配置控件、派生配置、数据模型、几何归属、验证输出和测试；不保留旧字段别名或兼容分支。

### 7. 保存允许 ROI 草稿，检测启动执行完整校验

配置保存和检测启动共享同一个 ROI 模式校验器，但采用不同完整度：保存时允许定位 ROI 和识别 ROI 尚未创建，并按 `null` 保留草稿；已经创建的 ROI 仍必须位于 `0..1`。保存时校验配置版本、定位类别非空、定位数量为正整数、待检类别非空且数量为正整数，但不把启动时已加载处理器的类别列表当作新模型的类别来源。保存成功后按新模型路径重载处理器。检测启动时必须使用重载后的实际模型类别核对定位和待检类别，并要求两个 ROI 均存在且有效。程序可在 ROI 草稿未完成时打开和保存，但不得启动推理判定；启动提示必须列出具体缺失字段，而不是只显示“配置错误”。

静态图片验收和打包冒烟必须复用同一配置校验和 ROI 引擎，避免源码 UI 可用但便携程序或离线验收仍走旧父区域逻辑。

## Risks / Trade-offs

- [定位只需一帧，偶发误检可能启动一轮] -> 定位数量必须精确匹配，手填定位类别在开始检测时必须属于实际加载模型；现场通过模型阈值和 ROI 范围降低误触发，不私自增加稳定帧。
- [完成间隔过短时同一批产品仍在定位区] -> 间隔到期允许重新触发是已确认语义，操作员按输送速度调整现有间隔。
- [固定 ROI 与相机硬件裁剪或机位变化不一致] -> 归一化坐标只解决分辨率/显示缩放；物理视野变化后必须刷新静态帧并重新配置 ROI。
- [精确数量对重复框和误检敏感] -> 保持现有置信度/NMS 调节和稳定帧；实际数量多于配置同样显示为数量异常。
- [删除旧配置导致其他电脑无法直接复用] -> 使用显式配置版本阻止错误检测，发布完整新版便携目录并要求现场重新配置。
- [重新打包覆盖现场已调好的配置] -> 构建脚本在 PyInstaller 清理便携目录前备份现有 `config.json`，构建成功后原样恢复；只有首次不存在用户配置时才生成默认配置。
- [删除父区域模块影响普通动作模式] -> 引擎创建由模式开关隔离，并用普通模式完整回归、相机清理和模型热重载测试约束。

## Migration Plan

1. 先增加新配置版本、双 ROI 数据模型和失败测试，验证旧配置被拒绝且普通模式不变。
2. 实现纯 ROI 轮次引擎及中心点包含函数，用单元测试固定定位、精确数量、分类锁存、FAIL 和间隔重置。
3. 新增 ROI 配置页面与静态帧编辑器，提供手填定位类别并在检测启动时执行实际模型强校验。
4. 接入主窗口、运行时 overlay、统计、声音、证据和离线图片验收。
5. 删除旧第一类别父区域配置、`pcb_inspection` 专用实现、UI、测试和文档引用，不保留兼容读取。
6. 生成新版默认配置和操作手册，运行聚焦/完整测试、严格 OpenSpec 校验、重新打包及真实便携冒烟。
7. 现场在其他电脑重新配置定位类别、数量和双 ROI，调节现有 PASS/FAIL 帧数与完成间隔，连续验证输送节奏。

回滚时恢复上一版完整便携目录及其旧配置文件；新旧配置不得混用。旧未归档 change 的归档或废弃在本变更实现并经用户验收后单独确认，本提案不自动归档。
