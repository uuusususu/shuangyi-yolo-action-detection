## Context

三种 ROI 的职责已经分开：模板 ROI 裁图建模型，搜索 ROI 限制运行时查找，识别 ROI 数类别。`roi-edge-template-locator-inspection` 也写了「保存模板不得因搜索 ROI 未完成而失败」。

当前 `ConfigPage._save_template_roi()` 却先取搜索草稿做余量校验，再在搜索框里 `find()`。没有搜索框或框太小就拒绝保存。点「创建/替换 ROI」还会立刻放默认框；搜索默认框正好包住模板默认框，强化了「必须套在一起」的错觉。这些默认框一点「保存当前 ROI」就会进 `config.json`。

## Goals / Non-Goals

**Goals:**

- 保存模板只依赖模板 ROI 和静态画面。
- 搜索框够不够大，只在开检或启用模板定位时检查。
- 未创建的 ROI 在编辑器和配置里都是空的；草稿不落盘。

**Non-Goals:**

- 不改形状匹配算法、金字塔或运行时「只在搜索 ROI 内查找」。
- 不改 YOLO、顺序/ROI 判定、同帧显示。
- 不恢复 PCB / 首类别 UI。

## Decisions

### 1. 模板回查用模板 ROI，不用搜索 ROI

`find()` 要求搜索窗大于旋转包围盒，所以不能把搜索窗刚好设成模板框。回查窗口从模板 ROI 向四周扩到 `min_search_size`，仍不够时退回整张静态图。坐标仍在原图上，便于画绿色外框。

备选：在裁剪图上加黑边再搜。效果类似，但要把框映射回原图，更容易错位。

### 2. 余量检查留在开检

`MainWindow._template_runtime_validation_error()` 已经检查已保存搜索 ROI。保存搜索框或模板时不再调用 `_search_headroom_error()`。现场可以先存小框，再改大后开检。

### 3. 创建只产生草稿

「创建/替换 ROI」只往编辑器放可拖拽草稿，不写 `config.json`。打开配置页只恢复已经保存的框。整页保存仍不覆盖三种 ROI。

## Risks / Trade-offs

- [模板回查扩到整图时，旁边相似轮廓可能得分更高] → 先扩模板 ROI；只有装不下才用整图。失败仍保留旧模板。
- [先存过小搜索框，开检才报错] → 报错文案继续给出所需像素尺寸。
- [已有配置里的历史框会继续显示] → 只保证未保存草稿不落盘；不自动清空现场已存框。

## Migration Plan

1. 改模板保存与搜索保存校验，更新配置页测试。
2. 确认开检路径仍拦截未保存或过小的搜索 ROI。
3. 回滚：只改配置页保存/回查，不改配置 schema。
