## Goals / Non-Goals

**目标：**

- 顺序模式只接受完整动作事件，一次结束的动作只结算一次。
- 零件证据严格属于同一个动作段，缺件和错序进入既有 NG / 证据 / 统计链路。
- 用已有权重实现连续在线 LSTM，保留训练的特征、标准化和解码语义。
- 模式、类别和模型错误明确可见；真实便携包和真实视频均有验收步骤。

**范围外：**

- 不重训 YOLO、MediaPipe、LSTM，不修改已有标注和训练结果，不修复训练数据质量。
- 不接入 MS-TCN、旧滑窗动作模型、同流程混用 YOLO 步骤、重复动作数量计数。
- 不增加物料数量或物料先后规则；`required_parts` 仍表示类别集合。
- 不自动生成业务步骤，不改 ROI / 纯 YOLO 的既有判定规则，不在本阶段修改产线代码、安装或部署。

## Decisions

### 1. 唯一模式路由与类别校验

| ROI 定位检测 | 步骤顺序约束 | 判定来源 | 配置类别的含义 |
| --- | --- | --- | --- |
| 开 | 任意 | 既有 ROI / YOLO | YOLO 零件类别 |
| 关 | 关 | 既有 YOLO 步骤判定 | YOLO 类别 |
| 关 | 开 | 连续 LSTM 动作＋段内 YOLO | 动作名称，如包装、封装 |

`lstm_action_enabled` 作为旧字段兼容读取，不再决定运行模式。界面去掉“LSTM 单独判过”的独立使能含义，按上表显示当前判定来源；顺序模式需要模型包路径。旧配置顺序开关已开启但没有模型包时，阻止启动并说明原因，不能继续静默按 YOLO 放行。

顺序模式：配置的非空动作名称去除首尾空格后，必须与模型非空闲动作名称集合完全相同，无重复，不允许子集、未知名或自动补全。**配置顺序决定 SOP；模型输出索引仍依照契约 `class_ids`。** 例如模型索引为“封装、包装”，配置顺序为“包装、封装”，通过 ID/名称映射识别，不能重排权重输出。

LSTM 步骤的数量只允许 1，界面将“同帧目标数量”灰显为不适用；不把旧数量值偷偷解释为动作次数。已有有效数量不为 1 时，要求用户改为 1 后保存。PASS/NG 稳定帧和类别数量失败重试不再重复施加到动作事件；纯 YOLO / ROI 沿用这些原参数。

### 2. 选择连续状态推理

考虑过三种方案：

| 方案 | 行为与代价 | 结论 |
| --- | --- | --- |
| 旧固定滑窗 | 实现少，但与连续训练的记忆和边界不同，容易动作未结束就 PASS | 不采用 |
| 每帧重跑累计片子 | 可作为离线对照，但运行时间和缓存随片长增长 | 只用于测试对照 |
| 保留 LSTM 隐藏状态＋增量切段 | 每个时间基样本执行一次，状态量有界，可输出完整事件 | 采用 |

在现有相机推理线程中执行 YOLO、手部和动作推理；同一份原帧与采集时间关联所有结果。GUI 不承担模型推理，不从显示帧率或界面消费速度推算动作时长。

调用既有 `ActionLSTM` 的相同 LSTM 和分类层，持续传递 `(h, c)`。eval 下，整条特征一次前向与分块前向的逐帧 logits 必须在明确容差内一致。运行默认先以 CPU 保证便携可运行，目标硬件达不到时间基时禁止业务放行；不在本次额外增加设备选择界面。

### 3. 部署模型包与名字映射

模型包包含：

```text
动作模型包/
  best_lstm.pt
  contract.json
  runtime_manifest.json
```

`contract.json` 和权重按原文件复制，部署清单新增 `manifest_version: 1`、有序 `action_classes: [{id, name}]`、契约 SHA256、权重 SHA256 和映射来源说明。动作清单包含 `idle`，名称映射必须完整覆盖契约 ID，每个名称唯一。它是模型元数据，业务步骤仍只有配置页的 `category_names` 一份。

提供独立准备工具生成新目录，不覆盖原 run。原 run 若有与该轮绑定的类别名元数据，直接使用；没有时必须显式提供 ID→名称映射或人工确认的映射文件。可以将工程标注里的 ID/名称列出作为候选，但不能未经确认就用当前工程名字、日志排列或配置步骤位置猜测历史模型名称。不要求为了补名字而重训。

产线仅接受 `network=lstm`、`train_unit=timeline`、受支持 `decode_version`，检查网络尺寸、类别、特征长度、均值/标准差长度和有限值、正时间基和最短段时长、YOLO / 手部文件指纹及手部复杂度。YOLO 阈值必须等于契约的 `yolo_conf_threshold`；它过滤零件，不充当 LSTM 概率阈值。动作类别沿用工作台 argmax，不新增概率门槛。

每个非空闲动作必须存在非空 `required_parts`，其类别必须属于契约零件名单。缺字段不能当作“不查零件”。该集合直接使用现有契约，既不按当前画面重算，也不在部署时修正。

### 4. 同帧特征、时间基与 ROI

模型特征调用 `build_feature_row`，顺序使用 `part_class_names`。内部手部数据必须保留像素 x/y 和 MediaPipe z；显示骨架可以继续使用二维投影，不能把显示用 payload 当模型输入。手部成功运行但未检出手，按训练规则填零；模型加载或推理故障必须标为故障，不能伪装为没检出手。

顺序动作模型使用原始整帧检测结果和整帧归一化，不能先用识别 ROI 删除框，也不能用模板未匹配时的空检测替代实际 YOLO 输出。保存的 ROI / 模板参数在该模式不参与特征和 PASS 门控；退出该模式后按既有规则生效。ROI / 模板逻辑的实现不作无关重构。

用采集的单调时间戳对齐契约时间基。固定帧率回放使用与工作台相同的 `resample_indices`；实时采样按时间格选择同一格中确定的真实帧，保留源帧号，允许最多一个采样间隔的因果选择延迟。不以处理 FPS 加速或拉长动作，不把同一源帧复制成多个有效样本。

实时输入缺少覆盖目标采样格的真实帧时，暂停产生完成事件；相邻有效源帧时间间隔超过 `2 / time_base_fps` 时进入流中断，清理时序会话并要求重新就绪。源帧号重复/倒退或时间戳回退同样中断。实现验收须覆盖该边界，而不是仅比较平均 FPS。

零件检查累计动作区间内所有实际处理过的源帧检测，不仅累计被选入 LSTM 时间基的帧。框必须达到契约 YOLO 阈值；短暂遮挡不撤销此前出现的类别。迟到的下一段零件不得补到上一段。

### 5. 完整动作与增量切段

逐帧分类和最短段合并沿用 `decode_version: 1` 的规则，与工作台 `build_segments` / `absorb_short_segments` 对照。不得仅凭若干帧命中就提前输出完整动作。

在线解码保留当前段、待确认后继段和少量边界证据：后继类别只有持续到契约最短段长度后，才能确认前段结束；短后继合回前段，相邻同类合并，开头短段处理也与离线一致。若有必要抽取共用辅助函数，保持离线输出不变，不在接入时重新设计去抖算法。

一个非空闲段只有在起点和终点都已观测后，才发出唯一 `ActionCompleted` 事件，字段包括：会话、事件编号、动作 ID/名称、起止采集时间、源帧范围、已见零件及出现证据、结算帧号和模型包指纹。缺项由同一事件计算，不由 GUI 重扫累计类别。

启动/恢复检测时可能正处在动作中间，因此第一段非空闲默认不可结算。先观察到稳定空闲，或先结束一个被丢弃的开头动作，才允许随后从新边界开始的动作参与 PASS。初始空闲后出现的首个动作可正常参与。停止、关相机、断流、错误和程序退出均不把未结束尾段强行结算为 PASS。

动作直接切到下一个动作时可形成边界，不要求中间一定有空闲。最后一步也必须等下一段稳定空闲或其他类别确认边界；持续保持同一动作类别时继续显示“动作进行中”。确认延迟约为最短段时长加采样/计算延迟，不能宣称动作结束当帧零延迟。

### 6. 动作事件进入顺序引擎

为顺序引擎增加动作事件入口，复用现有步骤状态、轮次结果及通知链路；不伪造 YOLO 检测框，也不把动作事件重复投递成多帧检测以凑稳定帧。

| 已结束事件 | 处理 |
| --- | --- |
| 空闲 | 只作为边界，不推进步骤 |
| 当前等待动作，零件齐全 | 当前步骤 PASS 一次，推进下一步 |
| 任一有效动作缺少契约零件 | 立即缺件 NG，结束本轮；即使是首步也不能放行 |
| 首步尚未 PASS 时出现其他完整且零件齐全的动作 | 按既有首步保护不触发错序 NG，不提前锁存未来步骤 |
| 首步已 PASS，出现未来未完成动作且零件齐全 | 完整事件直接触发错序 NG，结束本轮 |
| 已 PASS 动作再次完成且零件齐全 | 不重复 PASS，不用于下一轮 |
| 不属于模型清单的动作或坏事件 | 运行故障，停止业务判定并提示 |

同一完整动作发生缺件又越序时，优先报告缺件，同时在证据中记录预期步骤与实际动作。缺件不能跨重做或跨段补齐；本轮已经结束，不等待后面的零件。动作段内多余零件不导致 NG。

YOLO 原有每帧更新在该模式下完全退出步骤推进，尤其不能因为物体一直放在桌上，就绕过动作直接 PASS。纯 YOLO 和 ROI 模式不消费动作事件。

### 7. 轮次、冷却与故障

正常轮次结束和既有冷却期间，时序推理继续维持上下文，业务事件一律丢弃；进入下一轮时清空已见零件和事件消费账本的轮次状态，不重放冷却期间动作。跨越轮次边界的未结束动作不能归到新一轮，等待下一真实动作起点。

开始/停止检测、关闭/重开相机、模式或模型变更、流中断和模型推理故障属于硬重置：清除隐藏状态、采样状态、切段候选和全部零件证据，重新等待动作边界。正常产品轮次不是硬重置，避免每件产品都破坏连续训练的上下文。

模型故障与产品 NG 区分：故障立即停止放行、提示故障、保留原因，不额外增加产品 NG 数。已确认的缺件 / 越序按现有 NG 计数一次，并进入原来的结果展示、声音、证据与下一轮流程。

### 8. 界面、证据与配置保存

配置页仍由人填写动作类别和 SOP 顺序；模型包检查结果显示已识别动作名单、每类所需零件及模式状态，不自动修改表单。

主界面显示当前动作、进行中/等待结束/待就绪、当前已见和缺少零件；步骤卡只显示已结算状态。NG 证据优先绑定动作边界的真实源帧，同时记录决策帧与时间，不能将稍后其他动作的画面误标为缺件发生帧。复用现有 `fail_evidence` 出口；单事件只触发一次统计、声音和证据保存。

模型或模式配置采用候选校验后整体提交。修改前备份配置；候选失败时保留旧配置和旧处理器，明确显示保存失败；不能把失败候选的动作名称与旧 YOLO 处理器拼起来运行。已经运行的模型发生异常时，停止业务判定，不能静默切回旧 YOLO。

## Risks / Trade-offs

- 完整动作依赖结束边界，末步会延迟确认 → 提示“等待结束”，验收记录动作边界和决策时间；不在用户未知时改成进行中 PASS。
- 最短段合并本身会吞掉短空闲 → 本次保持工作台语义，加入连续 / 分块 / 真实回放对照，不把算法改良混入产线接入。
- 现有 `required_parts` 可能把偶然出现的类别也列为必需 → 原样展示并执行契约；标注或门禁规则调整另立任务。
- 产线手部漏检和模型误识别仍可能导致误判 → 本次验证接线和语义一致，现场效果必须另用真实视频和目标硬件验收，不能拿合成测试代替。
- 新模式改变旧顺序配置的启动条件 → 明示缺少模型包错误；需要继续 YOLO 的用户可显式关闭顺序约束，不能自动关闭。
- Torch / 手部运行时缺失，或目标机器速度不足 → 便携包真实加载、无源码目录 smoke、时间基覆盖检查，故障时停止放行。

## Migration Plan

1. 用户审核本目录；明确批准实现前不改代码，不执行 `apply`。
2. 获批后先建立流式等价、同帧深度、完整段门禁和模式回归测试，再接入最小代码改动。
3. 将选定 run 复制到新的部署模型包，补齐经确认的名称映射；不覆盖原 run，不更新权重。
4. 备份工位配置；在候选配置中选择模型包和相同动作名称，校验通过后提交。既有配置 schema 不因旧字段弃用而自动升级；若实现确实需要升级，必须在实施计划中单列迁移规则。
5. 用项目真实片子对照工作台最终稳定段，并核验缺件 NG、错序、首步保护、冷却隔离及目标便携包。
6. 交付验收记录和中文说明，等待用户确认是否符合预期；用户确认后才允许归档。
7. 回退时还原备份配置和旧可执行程序；不在新程序内部自动用 YOLO 替代失败的动作模型。

## Open Questions

没有阻止提案生成的业务问题。以下为本提案提出、等待审核的具体默认规则：

- 模型动作名称集合必须完全一致，但 SOP 顺序可独立配置。
- 完整动作必须等后继稳定段确认；开机时截断的动作不 PASS，停止不结算尾段。
- 顺序动作数量固定为 1；物料仅检查类别出现，不检查数量和先后。
- 首步之前只抑制错序 NG，不抑制缺件 NG；模型故障不计为产品 NG。

审核后仍需在实施验收中填写实际模型包、目标机器和逐项结果。这些是交付证据，不是本提案预先宣称通过的验收结论。
