## Context

现场 20 个包装/封装事件全部段内必检零件齐全，但旧业务逻辑误拒收 5 条，并连带错序。10 月 22 日的修复仍留下两步漏封装误 PASS、末步分段误 NG 和延迟 NG 证据缺失。现场事件层回放不等于人工动作准确率或相机验收。

## Goals / Non-Goals

目标：每个完整事件只归属一轮；缺步不能跨件补齐；显示停留不降低业务吞吐；NG 留下真正出错动作的图片和元数据。

不修改模型、置信度、训练数据、采样与切段算法，不通过超时补 PASS。ROI 与非 LSTM 模式继续使用原轮次间隔。

## Decisions

### 业务边界与首步规则

正常续轮沿用前轮结束事件的半开结束帧，等于边界的下一动作允许进入；开始检测和配置重载仍建立独立预览帧屏障。事件编号去重保持生效。

一个产品只接收一个完整 SOP 首步。旧轮首步已有结果时再次收到完整首步，以新首步 start_frame 结束旧轮，未做步骤记 NG，再仅在新轮处理该首步及其零件。正常续轮必须先看到首步，非首步尾部片段以 await_first_step 拒收，不制造额外 NG。全新检测会话的真实错序仍按原规则处理。

这里无法区分同件返工和新件：采用保守重新开件并记录前件缺步，优先避免漏封装 PASS。人工确认同件返工时，应根据现场 SOP 解释该 NG，不能无证据合并。

### 显示与业务处理解耦

GUI 对同一 overlay 中的每个事件立即判定并逐轮反馈，旧轮统计、声音和证据完成后再开始新轮。完整首步触发的换件事件只在新轮消费一次。显示定时器仅清理结果标签，不重置正在进行的新轮，不重新消费事件；配置更新不因显示标签停留而阻塞。

兼容低层暂存接口仍有 16 条上限，但正常 GUI 路径不依赖其排队等待。溢出抛出明确故障，GUI 停止检测和放行，保留原事件，不静默删最旧事件。

### 出错动作与图片所有权

步骤引擎保存实际出错动作的帧、缺件、时间与模型标识快照。后续合格步骤不能把整轮 NG 的上下文覆盖成最后一个合格动作。

相机发布完成事件时附带同边界图片快照和 runtime_generation；Qt 消息拥有该快照，底层最近四事件缓存驱逐不使未消费消息丢图。GUI 仅保留本轮出错边界及最近两个事件的图片，换运行代际不复用。优先取真实边界缓存，已驱逐时按帧号和运行代际校验消息快照；两者都缺失则明确记录无证据，不能拿最新画面冒充。

## Risks / Trade-offs

- 再次完整首步可能是返工：保守拆轮，不能用固定秒数猜测同件。
- 图片增加事件消息负载：仅在动作完成时携带，GUI 按失败步骤数加最近两条有界保留。
- 模型持续输出同一类别：没有确认结束事件就继续等待，本次不承诺修复该类输入准确率问题。
- 便携包通过本机自检不代表目标相机、曝光、光照和现场节拍已验收。

## Migration Plan

先运行源码与真实 GUI 入口回归，再在独立 production-delivery-20261026 目录构建。正确动作权重与配套 YOLO 放进包内，配置使用相对路径。保留旧交付包和原配置；现场退出旧程序，复制新包到新目录，先自检并确认相机与 SOP，再按现场测试表验证。需要回退时恢复旧完整目录。源码、模型、EXE 与 ZIP 的哈希及验证结果随交付保存，未经用户确认不归档。
