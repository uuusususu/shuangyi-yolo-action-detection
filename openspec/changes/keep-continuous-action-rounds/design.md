## Context

时序动作模式下，`TimelineSession` 把连续动作切成首尾相接的完整事件：上一动作的 `end_frame` 就是下一动作的 `start_frame`（现场日志：封装 68–103 后紧跟包装 103–150）。`StepSequenceEngine.apply_action_event` 用 `_action_min_source_frame` 挡住属于上一轮的动作，这个门槛由主界面 `_begin_step_round` 在冷却结束时取 `get_latest_preview_frame_id() + 1`。

现场问题链：

1. 第 1 轮在封装结束帧 103 判 PASS，约 1 秒冷却后第 2 轮开始，门槛 = 当时预览帧 109。
2. 下一件包装从 103 开始，`103 < 109` 被拒收（`before_round_start`）。
3. 下一件封装到达时本轮在等包装，判错序；本轮仍等包装，于是把再下一件的包装吃进本轮才结束，下一轮从封装开始，错位循环。
4. 冷却计时器运行期间到达的事件被主界面直接丢弃（`round_cooldown`）。

## Goals / Non-Goals

**Goals:**

- 连续作业时，每个完整动作都归属到正确的轮次，不因换轮被丢弃。
- 结果显示间隔只影响界面停留，不影响动作接收。
- 缺步、错序后本轮尽快结束，不跨件吞动作，下一件能正常判定。
- 现场 20 个事件重放得到 10 轮全部 PASS。

**Non-Goals:**

- 不改模型、切段算法、确认时长或训练流程。
- 不改检测类别（非时序）模式的轮次逻辑。
- 不改配置文件格式和配置页。

## Decisions

### 1. 新轮门槛取上一轮结束事件的结束边界

引擎在本轮因动作事件结束时记住 `_next_round_boundary`：正常结束取结束事件的 `end_frame`；换件结束（见决策 3）取触发事件的 `start_frame`。`start_round(continue_from_previous=True)` 有边界时用它作门槛，否则用调用方给的预览帧门槛。

主界面只有冷却结束后的自动换轮传 `continue_from_previous=True`；开始检测、配置重载、引擎重建仍用"当前预览帧 + 1"，并清空暂存队列，保证开机前、停机期间的动作不会混入。

备选：把门槛放宽为"预览帧 − 固定余量"。拒绝，余量与动作时长、冷却时长、推理延迟都相关，没有可靠取值。

### 2. 冷却期间事件进入引擎暂存队列

主界面在检测开启时始终把事件交给引擎，不再因冷却丢弃。引擎去重后，若本轮已结束则把事件放进有界队列（上限 16 条，超出丢最旧并记录）。`start_round` 在设置门槛后按顺序重放队列：每条仍经过门槛、空闲、缺件、顺序检查；若重放途中本轮再次结束，剩余事件留给再下一轮。

不延续上一轮的换轮（开始检测等）清空队列。检测关闭时事件仍按 `inference_off` 丢弃。

重放可能让新一轮立即出结果；主界面在换轮后本来就会调用 `_update_step_display`，会正常计数、出声并启动下一次冷却。

### 3. 缺步后的轮次恢复

- **单调推进**：某步得到结果（PASS 或 NG）后，它之前仍未出结果的已配置步骤立即判 NG，原因"未检测到<动作>"。这样最后一步出结果时整轮必定结束，不再等待被跳过的前序步骤。
- **换件**：事件对应的步骤已出结果，且该步骤位于本轮"已出结果的最靠后步骤"之前，说明下一件已经开始。本轮剩余步骤判"未检测到"并结束，门槛设为该事件 `start_frame`，该事件放回队列交给下一轮。
- 与"已出结果的最靠后步骤"同名的重复事件（同一动作被短暂停顿切成两段）仍按 `no_matching_step` 拒收，不触发换件。

备选：错序后保持旧行为继续等待。拒绝，这正是跨件错位的来源。

### 4. 追踪

新增 `event_decision` 原因：`queued`（暂存）、`queue_overflow`、`replayed` 标记，`round_rollover`（换件结束），以及 `round_start` 的 `boundary_source=previous_round|preview` 字段；`not_detected` 写入步骤原因。

## Risks / Trade-offs

- [两步配置下操作员跳过封装直接做下一件包装] → 第二个包装与已完成的包装同名，按重复拒收，下一件的封装会补齐本轮。这是对"同一动作被切成两段"的保守处理，已知会漏报一次缺步；三步及以上配置可由换件规则识别。
- [冷却很长时队列积压] → 队列有界，并在日志里记录溢出。
- [配置重载在冷却中触发引擎重建] → 新引擎没有边界和队列，回退到预览帧门槛，与现状一致。

## Migration Plan

纯运行时逻辑变更，随下一次便携包发布；回滚即恢复旧版本 exe。现场可用 `action_trace.log` 中 `boundary_source` 与 `replayed` 字段确认新逻辑生效。
