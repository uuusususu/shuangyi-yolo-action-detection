# 统一训练工作台设计（YOLO 零件检测 + LSTM 动作时序）

## 1. 当前边界

工作台目录保持 `lstm_workbench`，通过 Python 标准库 HTTP 服务监听 `127.0.0.1:8771`。前端沿用当前的浅色页面、原生 JS、Bootstrap 和 ECharts；产线 PySide6 程序有独立入口及发布流程。

工作台在既有零件训练、ONNX 模型库、动作标注、后台特征准备和动作训练上，集成原生 OBB 标注、数据审核与版本发布、零件验证、错例回流和动作标注完成确认，形成完整的训练与验证闭环。

旧设计中“不在工作台里做 YOLO 框标注”已被本轮用户确认的范围取代。外部 OBB 标注工具及 Ultralytics 数据集导入仍作为兼容入口。

## 2. 设计原则

1. 一条产线对应一个工程，零件与动作的数据、标注和轮次保持关联。
2. 原始标注工作区与发布版本分开：继续标注不能改变已发布数据和正在训练的输入。
3. 来源组整体划分训练、验证和测试集，减少同视频相邻帧泄漏。
4. 人工审核与模型预测分开：自动标注先待审核，空标签必须显式确认无目标。
5. 昂贵的设备任务共享互斥，保存标注使用独立的数据锁，不让长训练锁住普通编辑。
6. YOLO 使用独立 Python 子进程。运行环境按当前部署探测，不能假定开发机和便携 runtime 的版本完全相同。
7. 工作台只监听本机并沿用 Host、Origin、JSON 与文件路径校验；不为新页面放宽跨站写入边界。

## 3. 工程结构

```text
lstm_workbench/
  app.py                            HTTP 服务、请求保护、任务协调
  parts_store.py                    零件素材、OBB、审核、质检及发布
  yolo_jobs.py                      零件训练、追溯、续训与导出
  yolo_validation.py                验证/预标注记录与错例回流
  yolo_validation_worker.py         独立环境中的模型推理
  service.py / trainer.py           动作标签门禁与训练
  preparation.py / feature_store.py 后台特征准备及缓存
  static/                           原生 JS 页面与统一样式
  models/                           零件、底模与手部模型库
  projects/<工程>/
    parts/                          零件标注工作区
      images/                       工作区图片
      versions/<版本>/              冻结的数据集
      evaluations/<验证>/           验证及预标注记录
    yolo/                           旧格式数据集及零件训练轮次
      runs/<轮次>/                  权重、日志、曲线、参数和数据追溯
    media/                          动作视频或图像序列
    annotations.json                动作标注及完成确认
    features/                       逐视频连续特征缓存
    preparation.json                持久化后台准备请求
    runs/                           动作训练轮次
    settings.json                   工程设置
```

`parts/` 与 `yolo/` 平级，避免旧数据导入替换 `yolo/` 时破坏原生标注。LSTM 仍使用工程根目录的 `media/`、`annotations.json`、`features/` 和 `runs/`，不为本轮优化迁移旧工程目录。

## 4. 用户流程

零件流程：

```text
素材导入 → OBB 标注/预标注 → 人工审核/负样本确认 → 质检
  → 按来源发布固定版本 → 零件训练 → 独立验证 → 错例回流
  → 再审核、再发布、再训练 → 导出 ONNX → 在本工程启用
```

动作流程：

```text
选择零件模型 → 导入动作视频 → 动作段与不训练区间标注
  → 检查整条视频并确认空闲语义 → 选择训练/验证视频
  → 准备或复用连续特征 → 动作训练 → 结果与视频验证
```

后台特征准备可早于动作标注确认发生。确认约束的是标签可信度；修改动作边界不应使与标签无关的逐帧检测缓存失效。

## 5. 页面与交互

| 页面 | 职责 |
| --- | --- |
| 零件数据 | 已导入数据概况、原生素材/发布入口与兼容导入 |
| 零件标注 | 缩略图筛选、OBB 画布、类别、审核、质检定位、预标注及发布 |
| 零件训练 | 固定数据版本、底模和参数、训练进度与曲线、追溯、续训、ONNX 导出 |
| 零件验证 | 权重及数据选择、固定阈值指标、叠框、PT/ONNX 对照、错例回流 |
| 模型库 | 模型来源、指纹、工程使用情况与启用入口 |
| 模型与工位 | 动作特征所用模型及配置 |
| 数据与标注 | 动作素材、时间轴、整条视频完成确认 |
| 动作训练 | 视频勾选与训练/验证用途、后台准备、训练进度 |
| 动作结果 | 曲线、指标与检查视频 |

新页面沿用当前 `styles/tokens.css` 和页面壳，OBB 补充样式放独立文件，不重绘全站主题。画布快捷键只在画布获得焦点时生效；切页清理任务和监听，异步回包需核对工程及素材标识。

保存状态必须区分未保存、保存中、已保存和失败。乐观修订冲突不得静默覆盖。训练进度沿用网页内的任务控件，保留停止入口，避免只在终端输出。

## 6. 数据及指标口径

- OBB 采用类别编号和四个归一化顶点；保存前检查有限值、范围、凸性和面积。
- 发布只接收已审核目标和显式确认的负样本。未标注和待审核素材阻断发布。
- 数据版本冻结类别顺序、图像、标签、来源组、集合划分及内容指纹。
- 每轮训练记录固定数据版本、模型指纹、环境和参数；续训使用本轮 `last.pt` 及原数据。
- 独立零件验证的 TP/FP/FN、精确率、召回率和 F1 对应指定阈值，不等于 mAP。
- PT 与 ONNX 对照使用相同样本和推理设置，输出差异不自动等于现场效果差异。
- 动作旧工程缺失完成状态时视为未确认；参与训练和验证的视频都需要人工确认完整标注。

## 7. 后端接口分组

| 接口组 | 主要用途 |
| --- | --- |
| `/api/projects/<id>/parts` | 工作区概况、类别、素材导入、单图保存、图片读取、质检与发布 |
| `/api/projects/<id>/yolo` | 旧数据导入、零件训练、轮次曲线/日志/文件、ONNX 导出与启用 |
| `/api/projects/<id>/yolo/runs/<run>/resume` | 检查条件并从本工程断点恢复 |
| `/api/projects/<id>/yolo/validate` | 启动独立验证 |
| `/api/projects/<id>/yolo/preannotate` | 启动待审核预标注 |
| `/api/projects/<id>/yolo/evaluations` | 查询验证/预标注记录及错例回流 |
| `/api/projects/<id>/annotations` | 保存动作标注与完成确认 |
| `/api/projects/<id>/preparation` | 后台特征准备、暂停、恢复及重试 |
| `/api/projects/<id>/stop` | 停止本工程当前设备任务 |
| `/api/models` | 模型库及使用关系 |

精确参数与返回值以对应处理函数和集成测试为准。本表不能代替 API 校验；长任务需要可轮询的持久状态，失败、停止和服务中断必须有明确结果。

## 8. 验收与限制

分层验证素材与版本存储、训练命令及追溯、请求保护、动作确认门禁，再以临时工程验证浏览器完整流程。新增关键模块统计覆盖率，完整工作台跑 CPU 回归。真实模型冒烟、GPU 训练、断点恢复和产线验证分别记录，不用假检测器通过代替现场精度结论。

本轮不引入外部任务队列、SAM/VLM 服务或新的大模型下载，不改产线阈值、采集参数和生产部署。目录名保持 `lstm_workbench`；便携环境与开发环境的具体库版本由探测结果和交付记录说明。
