# 因果 MS-TCN++ 小模型训练方案（无额外状态机）

日期：2026-09-20  
约束：**运行时不加相位状态机。** 小模型直接判断「整段动作是否做完」，做完就 PASS。  
三个运行模型：MediaPipe Hands（谷歌）+ 已有 YOLO OBB + 本方案训的因果 MS-TCN。

## 1. 和上一版差在哪

上一版对内拆 `idle/pickup/insert/done`，再用状态机按序合并。现改为：

- 小模型只出两类：`incomplete`（未完成）/ `complete`（整段做完）
- 软件里：**TCN 说 complete，并连续稳住现有的通过帧数 → 该步 PASS**
- 不写 pickup→insert→done，不记「前面相位到过」

「必须做完整段」写进**训练标签和窗口长度**，不写进运行逻辑。

## 2. 训什么、不训什么

| 东西 | 做不做 | 说明 |
| --- | --- | --- |
| YOLO OBB | 不训 | 只提供框，给特征用 |
| MediaPipe Hands | 不训 | 只提供 21 点 |
| 因果 TCN | **只训这个** | 看过去 T 帧，当前是不是「动作已完成」 |
| 相位状态机 | **不做** | 完成由模型直接出 |
| 通过稳定帧 | 沿用现有 `action_pass_stable_frames` | 防单帧抖动，不是新状态机 |

## 3. 模型怎样在没有状态机时仍等整段做完

因果 TCN 在第 t 帧能看见窗口里 t 之前的全部特征。把「完成」**只标在整段做完之后的那几帧**，拿起、套入中、只拿起就放下全部标 `incomplete`。

模型要输出 `complete`，窗口里必须已经出现过靠近→接触→离开这类轨迹。刚拿起时窗口里没有结束，标签也是 `incomplete`，分数上不去。

因此：

- **窗长 T 必须盖住一次完整动作**（建议 64～128 帧，约 2～5 秒，按现场节拍改）
- 半截循环全程 `incomplete`，一条 `complete` 都没有
- 零件已经摆好、手没做过：也标 `incomplete`（防「看起来像做完」）

标注可以只标完成段，比四段相位更简单：

```text
# bag_001.csv  只写完成区间，其余帧自动 incomplete
complete,161,200
```

半截循环：空 CSV，或没有任何 `complete` 行。

## 4. 采集

现场用当前程序开检测，手部骨架打开。一次循环一条样本。

```text
yolo_action_detection/data/action_train/
  raw/
    bag_001/frames.jsonl      # 每帧 detections + hands + frame_id
    bag_001/video.mp4         # 可选，方便标「做完从哪一帧开始」
    bag_pickup_only_01/       # 只拿起就放下，无 complete
  labels/
    bag_001.csv               # 仅 complete 起止
    bag_pickup_only_01.csv    # 空，或零行
  features/
    bag_001.npz
  splits/
    train.txt
    val.txt
```

`frames.jsonl` 一帧最少：

```json
{
  "frame_id": 81,
  "image_w": 1920,
  "image_h": 1080,
  "detections": [
    {"label": "袋", "conf": 0.91, "center": [900, 500], "box": [800, 400, 200, 220]}
  ],
  "hands": [
    {"handedness": "Right", "points": [[x, y], "...21"]}
  ]
}
```

不要用 jpg 训 TCN。可用现有坐标日志瘦身，或录像回放同一套 YOLO+Hands，保证和线上一致。

| 类型 | 条数 | 标签 |
| --- | --- | --- |
| 标准做完 | 40–80 | 结尾若干帧 `complete` |
| 只拿起放下 | 15–20 | 全程 `incomplete` |
| 做到一半松开 | 10–15 | 全程 `incomplete` |
| 目标已在位、手不作业 | 10 | 全程 `incomplete` |
| 不同人 / 快慢 | 每人 ≥10 条完整 | 防过拟合 |

按**循环**划 8:2，验证集必须含半截和「已在位不作业」。不要按帧随机切。

## 5. 特征（与线上同一函数）

以当前步骤目标为原点：

1. 目标在场、conf、cx、cy、w、h（画面归一化）
2. 2 手 × 21 点，相对目标中心 / 对角线；缺手填 0 + 可见位
3. 指尖距离、掌心距离、接触、手框∩目标 IoU
4. Δ距离、掌心位移（轨迹，静态「已套好」和「刚做完」靠这个区分）

`X: (T, F)`，`y: (T,)`，取值 0=`incomplete`，1=`complete`。

## 6. 怎么训

- 输入 `(B, T, F)`，T=64～128，与线上缓冲一致
- 2 stage × 8 层膨胀卷积，通道 64，**因果卷积**
- 输出每帧 2 类，或一个 `p(complete)`
- 损失：带权重的交叉熵（`complete` 帧少，权重要加大）+ 相邻帧平滑
- 增强：时间拉伸 0.7～1.3、随机丢帧、点坐标微抖
- Adam 1e-3 → 1e-4，早停看下面的「半截误完成」

先用 LSTM-128 二分类把数据管线跑通，再换因果 TCN。标签始终是 incomplete/complete。

不要用 [sj-li/MS-TCN2](https://github.com/sj-li/MS-TCN2) 的双向卷积。

## 7. 线上怎么 PASS（无状态机）

```
每帧:
  YOLO + Hands → 特征 F_t → 推进长度 T 的队列
  TCN 看整窗，取最后一帧 p(complete)
  p(complete) ≥ 阈值（如 0.7）→ complete 命中 +1
  否则 complete 命中清零

  complete 命中 ≥ 现有通过稳定帧 → 该步 PASS
```

不记录有没有拿起过、有没有套入过。不写相位表。

丢手：点填 0，窗口继续；不要改回「只看 YOLO 数量」。数量命中若还要，可作并行条件，但完成仍以 TCN 为准。

## 8. 怎样算训好了

| 指标 | 合格线 | 含义 |
| --- | --- | --- |
| **半截误完成** | = 0 | 只拿起 / 做到一半，全程不能出 complete |
| **已在位误完成** | = 0 | 零件摆着不动不能过 |
| **完成过早** | 预测 complete 比标注早 >0.3s 的循环 < 10% | 刚拿起就响会在这里 |
| 漏完成 | 完整循环从未 complete < 5% | 别为防提前把真完成掐死 |
| complete 段 F1 | ≥ 0.80 | 结束点大致准 |

验收画每条循环的 `p(complete)` 曲线：完整循环只在末尾升高；半截应贴近 0。

## 9. 接到现有程序

1. 导出 ONNX：`[1, T, F] → [1, T, 2]` 或 `[1, T, 1]`
2. `StepSequenceEngine`：当前步的「命中」改为 TCN complete，不再用类别出现计数当充分条件
3. 稳定帧沿用配置里已有的通过帧数
4. 对外步骤名仍是「套袋」等业务名，与模型两类无关

## 11. 不要做的事

- 运行时再加 pickup→insert→done 状态机（本版明确不做）
- 整段图都标 complete / 都标「套袋」
- 窗长短于一次动作（模型没看见过程就会靠最后姿势误过）
- 验证集没有半截和「已在位」
- 官方离线双向 MS-TCN++ 直接实时跑
