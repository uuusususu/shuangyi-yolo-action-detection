# 检测时按有无加载 ROI

日期：2026-09-09  
状态：待实现  
范围：开始检测时按「有效框 / 可加载模板」组装可选层。顺序识别与不按顺序识别都按 `category_counts` 计数。不改步骤引擎、ROI 引擎的数量公式，不升 `config_schema_version`。

## 背景

三种 ROI 已经能在配置页创建并单独保存，但运行时被「启用 ROI 定位检测」挡住：开关关掉（顺序识别）时，已保存的识别 ROI、搜索 ROI、模板一律不读、不画、不挡。现场在顺序识别里框了识别 ROI，检测时等于没配。

模板 ROI 只在创建模板时裁图，检测时本来就不是运行框。

## 目标

- 有有效识别 ROI：检测时只把中心落在框内的目标交给判定。
- 识别 ROI 空或非法：整图计数，不拦启动。
- 搜索 ROI 有效且模板文件能加载，并且模板开关打开：先在搜索 ROI 内定位，命中才跑 YOLO。
- 搜索、模板缺一样，或模板开关关掉：不做定位，不报「未配置」。
- 模板文件在但损坏：拦启动，写明是模板坏了。
- 「启用 ROI 定位检测」只切换认法，不决定框加不加载。两种认法都按配置数量计数。

## 非目标

- 不改 `StepSequenceEngine` / `RoiInspectionEngine` 的「刚好等于配置数量」公式、稳定帧、错序、失败重试。
- 不把模板 ROI 当成检测过滤框或定位搜索框。
- 不因「有框」自动切换认法。
- 不升配置版本，不加新字段。
- 不改 MediaPipe Hands：仍只在顺序识别且检测中启用。

## 已定决策

1. 判定模式保留，ROI 改成可叠加层。
2. 顺序识别时，有效识别 ROI 只认框内目标；空则整图。
3. 顺序识别时，搜索 ROI + 模板齐全且开关开，则先定位再 YOLO，再用识别 ROI 过滤。
4. 两种认法都按 `category_counts` 计数。开关不是「一边顺序、一边才计数」。

## 认法（开关）

`roi_inspection_enabled` 只切换认法：

| 开关 | 认法 | 数量 |
| --- | --- | --- |
| 关 | 按步骤顺序推进 | 每一步该类别数量刚好等于该步 `category_counts` |
| 开 | 不按顺序；若做了定位，定位命中后再检 | 本轮所有已配类别同时按各自 `category_counts` 精确计数 |

两种都数数量。框是否加载与此开关无关。

`roi_template_enabled` 只做手动关闭：文件和搜索框都在，也可以先关掉定位，不必删文件。打开但东西不齐，当没开，不报错。

## 检测时加载规则

开始检测、以及「验证并保存」后若正在检测，按磁盘上的有效配置重新组装。零面积、缺字段、坐标不在 0..1 的旧框一律当空，打警告日志，不当启动错误。

| 已有内容 | 顺序识别（开关关） | 不按顺序（开关开） |
| --- | --- | --- |
| 识别 ROI 有效 | YOLO 之后只把中心在框内的目标交给步骤引擎 | 只数框内 |
| 识别 ROI 空 / 非法 | 整图都参与步骤 | 整图计数，不因缺框拦启动 |
| 模板开关开，且搜索 ROI 有效，且模板文件能读到 | 先在搜索 ROI 匹配，命中才跑 YOLO | 同左 |
| 搜索或模板缺一样，或模板开关关 | 不做定位，YOLO 照常，不报错 | 同左 |
| 模板文件在但读失败 / 损坏 | 拦启动，说明模板损坏 | 同左 |
| 模板层会启用，但搜索框平移余量不够 | 拦启动，沿用现有「搜索框太小」文案 | 同左 |
| 模板 ROI | 检测不用，只在创建模板时裁图 | 同左 |

「有效矩形」：能通过现有 `NormalizedRect.from_mapping`。`None`、空对象、校验失败都当空。

## 数据流

```
开始检测 / 保存后重建
  → 读 config
  → 识别 ROI 有效？ 是：挂过滤层；否：不过滤
  → 模板开关开 且 搜索 ROI 有效 且 模板文件可读？
        是：processor = TemplateGatedProcessor
        否：普通 YOLO processor（不报未配置）
  → 模板文件存在但 load 失败：拒绝开始检测

相机帧
  → processor（可选门控）
  → overlay.detections（整图结果，框外目标仍可画框）
  → 判定入口
        识别 ROI 有效：只保留中心在框内的 detections
        然后
          开关关 → StepSequenceEngine.update(过滤后)
          开关开 → RoiInspectionEngine.update(过滤后；无识别框则视作整图)
```

判定和画面分开：框外目标可以继续画检测框，但不推进步骤、不计入数量。

主画面：识别 ROI、搜索 ROI 有效就画。模板 ROI 检测时不画。不按顺序且启用了模板时，现有「只画搜索 ROI」改为：有效的识别 ROI 与搜索 ROI 都画。

## 改动边界

| 位置 | 改什么 |
| --- | --- |
| `main.py` `_wrap_with_template_gate` | 不再要求 `roi_inspection_enabled`。条件改为：模板开关开 + 搜索 ROI 有效 + 模板文件可加载。缺一样返回未门控 processor，不抛「搜索 ROI 未配置」。文件损坏继续抛错。 |
| `config.py` `inspection_validation_errors` | 缺框、非法框不再列入启动/保存错误。模板开关开但框不齐，也不因「未配置」失败。类别名、数量、阈值、角度等仍校验。 |
| `main_window.py` `_template_runtime_validation_error` | 不再要求 ROI 认法开关。仅在模板层会实际启用时检查：processor 已门控、模型能加载、搜索余量够。模板层不会启用时返回空字符串。 |
| `main_window.py` `_on_overlay_updated` | 喂给步骤引擎前按识别 ROI 过滤。ROI 引擎在无识别框时按整图计数（引擎入参使用整图矩形，或跳过中心包含判断）。 |
| `main_window.py` 画框 | 两种认法下，有效识别 ROI / 搜索 ROI 都画。 |
| `main_window.py` 开始检测 | 不再因缺识别 ROI 拒绝不按顺序认法。引擎初始化失败只保留「类别/数量无效」这类真错误。 |
| 配置页保存 | 不变：三种框只由「保存当前 ROI」写入；底部「验证并保存」不覆盖框草稿。 |

共享一个「矩形是否可用」函数（建议放在 `roi_inspection/geometry.py`），配置校验、门控组装、过滤、画框都走它，避免各处对脏数据解释不一致。

`RoiInspectionConfig.from_config`：识别 ROI 空时不得再强制 `NormalizedRect.from_mapping(None)` 失败。改为整图 `{x:0,y:0,width:1,height:1}`，或引擎在无框时跳过包含判断（两者等价，实现选一个，测试按「空框 = 整图」断言）。

本轮 `template_enabled` 以「门控是否真正挂上」为准，不以开关字面为准。开关开但搜索或模板缺一样、层没挂上时，不按顺序认法必须按无模板触发（识别 ROI 或整图内出现待检类别即开轮），不能一直等 `template_match`，否则「缺了不拦启动」会变成永远等定位。

## 错误处理

| 情况 | 行为 |
| --- | --- |
| 识别 / 搜索 / 模板框空 | 跳过对应层，不拦启动 |
| 框字段非法、越界 | 当空，打 `WARNING`，不拦启动 |
| 模板开关开、文件缺失 | 跳过门控，不拦启动 |
| 模板文件存在但损坏 / 点数不足 | 拦启动，文案含「定位模板」和具体原因 |
| 模板层启用且搜索余量不够 | 拦启动，现有「搜索框太小」文案 |
| 模板层启用但当前 processor 尚未门控 | 拦启动，提示先「验证并保存」 |

## 测试

新增或改现有测试，锁住：

1. 顺序识别 + 有效识别 ROI：中心在框外的目标不推进步骤；框内推进。
2. 顺序识别 + 空 / 非法识别 ROI：全部目标参与步骤；启动不报「识别 ROI 未配置」。
3. 顺序识别 + 模板开关开 + 搜索 ROI + 可加载模板：processor 为 `TemplateGatedProcessor`。
4. 顺序识别 + 只有搜索 ROI、没有模板文件：普通 YOLO processor，启动不失败。
5. 不按顺序 + 空识别 ROI：整图计数，启动不失败。
6. 整页「验证并保存」不覆盖已单独保存的三种框。
7. 非法旧识别框当空：顺序识别不按脏框过滤。
8. 模板文件损坏：开始检测被拒绝，错误提到模板。
9. 主画面：顺序识别下有效识别 ROI 会画出来。
10. 框外目标：overlay 仍带该 detection（可画框），步骤引擎收不到它。

现有 ROI 计数、模板自检、Hands 仅顺序启用的测试保持通过。原先「ROI 模式缺识别框必须失败」的用例改为「空框整图计数」。

## 风险

配置里可能留着以前试出来的识别框。改完后顺序识别会突然只认那一块。靠「非法当空」挡不住「合法但过时」的框。现场升级后若行为突变，先看主画面是否画出了旧识别框；不对就删框再保存当前 ROI，或重新框选。

## 实现顺序

1. 抽出「矩形是否可用」，改校验：缺框不报错。
2. 门控组装与开始检测校验改为按层启用，顺序识别也能挂模板。
3. 判定入口过滤识别 ROI；空则整图。
4. 两种认法画有效识别 / 搜索框。
5. 按上面 10 条补测试并跑 `yolo_action_detection/tests`。
