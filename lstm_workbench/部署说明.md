# 训练台部署说明（离线电脑）

## 部署

1. 把整个 `lstm_workbench` 文件夹复制到目标电脑，放在任意目录（路径可以有中文）。
2. 双击 `启动训练台.bat`，本机浏览器自动打开 [本机训练台](http://127.0.0.1:8771/) ；同时黑色启动窗口会打印本机**内网访问网址**（如 `http://192.168.1.x:8771/`），页面右上角也可一键查看并复制内网网址。
3. **网线直连 / 局域网跨机推送数据**：首次需要内网其他电脑访问时，在训练机上双击运行一次 `放行内网端口.bat`（放行 Windows 防火墙 TCP 8771 入站端口）。之后采集电脑用网线连上即可在浏览器打开该内网网址，直接拖拽推送图片、采集视频或数据集 `.zip` 包。
4. **内网安全保护（PIN 口令与只读模式）**：在运行训练台的本机打开页面，点击右上角 `内网 · 192.168.x.x:8771` 按钮，即可一键开启 **4~32 位访问口令（PIN）**（远端设备输入口令后解锁，本机免密）或切换 **内网只读模式**（远端仅查看图表与下载 ZIP，禁止删改或启停训练）；也支持命令行传 `--lan-pin <口令>`、`--lan-readonly` 或 `--local`（仅本机监听）。关掉黑色窗口就停止训练台。

不用联网，不用装 Python 或任何依赖。目标电脑只需要：

- Windows 10/11 64 位
- NVIDIA 显卡和**已经装好的显卡驱动**（驱动无法随包携带）。没有显卡也能用，训练改用 CPU，会很慢。

## 文件夹里有什么

| 目录 | 内容 |
|---|---|
| `runtime\` | 独立的 Python 3.11 运行环境：PyTorch（CUDA 12.8）、Ultralytics 8.4.102、MediaPipe、OpenCV、ONNX Runtime 等。动作训练和零件训练共用这一套。 |
| `models\yolo\` | 模型库：导出的零件模型 `.onnx` |
| `models\yolo_base\` | YOLO 底模（yolo11n-obb.pt、yolo26n.pt 等）和画图字体。离线训练从这里起步，不要删。 |
| `models\hands\` | 手部模型 |
| `projects\` | 所有工程：零件数据、动作片子、标注、训练结果。换电脑时连同这个目录一起复制就能接着用。 |

实际依赖版本以该交付包的运行环境探测结果为准。开发机 `.venv`、独立 YOLO 环境和复制的 `runtime` 可能不同，不要只依据表中的版本号判断兼容性。

## 使用流程

1. 首页新建工程（一条产线一个工程）。
2. **零件标注**：本轮优化接入图片、目录及视频抽帧素材，在工作台内编辑 OBB；逐图审核或显式确认无目标，通过质检后按来源组发布固定数据版本。视频抽帧只用于零件图片，不改变动作视频与连续特征。
3. **零件数据**：也可填已有 Ultralytics 数据集的 `data.yaml` 路径导入，兼容 X-AnyLabeling / CVAT 等外部工具。缺少来源信息的旧数据集不能证明训练与验证来源独立。
4. **零件训练**：选择已发布版本和 `models\yolo_base` 中的底模，填写参数；每轮保留数据及环境追溯。有效 `last.pt` 可用于断点续训，具体恢复条件看轮次提示。训完可导出 ONNX，再在本工程启用。
5. **零件验证**：使用相同样本检查 PT/ONNX，查看固定阈值的逐类指标、叠框与耗时，将错例回到标注页重新审核发布。这里的精确率、召回率和 F1 不等于 mAP。模型预标注必须人工审核后才能进入发布数据。
6. **模型库**：查看零件模型及工程使用关系。
7. **模型与工位 → 数据与标注 → 动作训练 → 结果**：检查整条动作视频，确认未涂区间为空闲后保存。旧工程没有完成确认的视频需要复核。未确认仍可提前准备特征，但不能用于动作训练。换零件模型或特征提取设置会使相关缓存需要更新。

完整闭环功能与设计边界详见 [统一训练工作台设计](../docs/统一训练工作台设计.md)。升级时需同时更新代码与静态页面。

注意：

- 显卡任务互斥：零件训练、验证、预标注、特征准备及动作训练不能同时抢占设备。使用网页内停止入口，并确认任务确实结束后再开始下一项。
- 底模只能用 `models\yolo_base` 里有的。填了没有的官方名，Ultralytics 会尝试联网下载，离线电脑上会失败。
  要用别的底模，在开发机上下载好放进这个目录再复制过来。

## 升级与备份

更新代码或运行环境前先确认没有训练、验证、预标注或特征准备任务在运行，再停止服务。备份整个 `projects` 目录，至少保留各工程的 `annotations.json`、`settings.json`、`preparation.json`、`parts` 和训练轮次；同时记录模型库对应文件。

新版零件素材和已发布数据集位于 `<工程>\parts\`；旧格式数据和零件轮次仍在 `<工程>\yolo\`。不要只复制最新图片或覆盖 `data.yaml`，否则会丢失发布版本、审核状态、来源和训练追溯。

升级后先用临时工程检查素材导入、保存、发布和模型推理，再打开实际工程。已经保存的版本不随工作区修改；动作旧工程缺少完成确认状态时需要人工复核。完整迁移、真实 GPU 训练和现场效果需分别验证。

## 产线

产线程序加载模型库里的 `.onnx`：把选定文件复制到产线 `config\` 目录，在产线配置页选它。

## 在开发机上重新生成 runtime

升级了依赖或 Ultralytics 以后，在开发机（能跑训练台的那台）的仓库根目录运行：

```bat
.venv\Scripts\python.exe lstm_workbench\make_offline_runtime.py
```

会重建 `lstm_workbench\runtime\` 并自检（导入全部库、检测显卡）。PySide6、pytest 这类训练台用不到的包不打进去。
Ultralytics 默认取同级 `ultralytics-main\ultralytics` 的源码（8.4.102），可用 `--ultralytics <目录>` 指定。

`runtime\` 有好几个 GB，已加进 `.gitignore`，不进仓库。
